3.1 Definition and Introduction

Gerald Lê Draft

01. What is ROS?

ROS (Robot Operating System) is not an operating system in the usual sense. It is an open-source collection of software libraries, tools and conventions for building robot applications, and it runs on top of an ordinary operating system such as Linux. It began in 2007 at Stanford and the robotics company Willow Garage. Today it is stewarded by the Open Source Robotics Foundation, which since 2024 has run the project through the Open Source Robotics Alliance, together with a large community.

ROS gives developers a common way to structure robot software and a huge library of reusable packages for things like navigation, manipulation, simulation and visualization. Its main building blocks are:

  • Nodes: independent programs, each responsible for one job, such as reading a sensor or planning a path.
  • Topics: named channels that nodes publish messages to and subscribe to, for continuous data like sensor readings.
  • Services: request/response calls between nodes, for quick one-off questions.
  • Actions: long-running goals with feedback, such as “drive to this point.”
  • Parameters: configuration values a node reads at start-up or while running.

02. Nodes, publishers and subscribers

ROS splits a robot’s software into nodes, separate programs that communicate by publishing and subscribing to messages. A mobile robot’s navigation software is a good example:

  • Sensor nodes: publish raw data, such as distance scans from a LiDAR.
  • SLAM (simultaneous localization and mapping): builds a map from that data while tracking where the robot is on it.
  • Path planning: finds a route with graph-search algorithms such as A* or Dijkstra’s, over a costmap that marks areas near obstacles as expensive.

03. Parameters and domains

In ROS 1, a central server (roscore) held every parameter in one global store. In ROS 2 there is no central server, so each parameter belongs to a specific node, and you read or change it by naming that node.

ROS 2 also uses a domain ID to keep groups of robots apart on a shared network. Nodes on the same domain discover and talk to each other; nodes on different domains cannot. Every node uses domain 0 by default, so on a shared lab or school network, setting a different value in the ROS_DOMAIN_ID environment variable keeps your robot from hearing someone else’s: 

export ROS_DOMAIN_ID=7

04. Where ROS came from

ROS grew out of the Personal Robotics Program in Ken Salisbury’s lab at Stanford, run by Eric Berger and Keenan Wyrobek, which drew on Morgan Quigley’s Switchyard software from Stanford’s STAIR robot project.
