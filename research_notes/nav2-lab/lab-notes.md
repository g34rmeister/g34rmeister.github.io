# Verified facts for the Nav2 lab (checked by Claude, 2026-11-11)

Each line says what was checked and where. The drafting ticket may use these as facts about the lab itself (no citation needed for statements about what the run showed); facts about Nav2 or RoboStack in general still need a citation to a file in `sources/`.

- Install: `install-transcript.md`. ROS 2 Lyrical and Nav2 come from the RoboStack channel `robostack-lyrical` with micromamba, in user space, no sudo. The documented create command took 11 s here because the packages were already in micromamba's cache from a first install; a first install downloads several GB (the first environment plus cache used 9.8 GB on disk; a second environment sharing the cache took 6.7 GB as reported by du, mostly hard links). Say "several gigabytes"; do not give a download time.
- Versions in the run: Ubuntu 26.04.1 LTS, micromamba 2.10.0, Python 3.14.10, ros-lyrical-ros-base 0.13.0, nav2_bringup 1.5.2, nav2_loopback_sim 1.5.2, nav2_simple_commander 1.5.2, nav2_minimal_tb3_sim 1.3.0. The references point to the `lyrical` branch on GitHub, which is at 1.5.3; the files used by the lab (launch file, nav2_params.yaml) are identical, and robot_navigator.py differs by one line unrelated to the lab.
- The apt install from lesson 4.3 was NOT tested with this lab. Say that the same commands should work there, and that this was not tested.
- Launch: `ros2 launch nav2_bringup tb3_loopback_simulation_launch.py use_rviz:=False`. The installed file name uses `_launch.py`; the loopback README writes `tb3_loopback_simulation.launch.py`, which does not exist in the installed package. `use_rviz` is a launch argument with default `True` (launch file source). `use_rviz:=False` was used because the run had no display; learners with a desktop can leave it out to see RViz (not tested here).
- Map: the launch file's default map is `tb3_sandbox.yaml` (launch file source). Its metadata: resolution 0.05 m per pixel, origin (-10, -10). Starting at (0, 0) did not work in an exploratory run: one goal "succeeded" with no motion, another failed with planner error code 208 ("Failed to create plan with tolerance of: 0.500000"). (-2.0, -0.5) worked in every run. Do not claim why (0, 0) failed; say it did not work in our runs and to use (-2.0, -0.5).
- Initial pose is required: the loopback README says the simulator accepts the standard /initialpose topic. In the runs, bringup paused at "Activating planner_server" with repeated messages "Timed out waiting for transform from base_link to map", until the pose was published. In an exploratory run where the pose came late, bringup aborted 60.5 s after "Activating planner_server" with "Failed to activate global_costmap because transform from base_link to map did not become available before timeout" and "Failed to bring up all requested nodes. Aborting bringup." (`run1/launch-late-pose-tail.txt`). Afterwards the servers stayed `inactive [2]` and Nav2 had to be restarted. This 60 s is what the log showed, not a value in nav2_params.yaml.
- Lifecycle check: after "Managed nodes are active", `ros2 lifecycle get` printed `active [3]` for planner_server, controller_server and bt_navigator in run2. In run3 the first query, made right after bringup, printed `Node not found` and the next two printed `active [3]`. Advice: if a ros2 command says Node not found right after startup, wait a few seconds and run it again (observation, no citation).
- `ros2 action list` printed 18 actions (transcript), including /navigate_to_pose, /compute_path_to_pose, /follow_path, /follow_waypoints, /spin, /backup, /wait.
- Goal from the command line, run3: about 9 s of navigation time, 909 feedback messages, result error_code 0, status SUCCEEDED. Robot before: (-2.000, -0.500); after: (1.292, -0.591), which is 0.23 m from the goal (1.5, -0.5): sqrt(0.208^2 + 0.091^2) = 0.227. nav2_params.yaml sets `xy_goal_tolerance: 0.25` and `yaw_goal_tolerance: 0.25` for the controller's `general_goal_checker`, so 0.23 m counts as reached. Run2 gave 900 feedback messages and (1.293, -0.591).
- Feedback fields seen: current_pose, navigation_time, estimated_time_remaining, number_of_recoveries, distance_remaining, position_tracking_error, heading_tracking_error. Result fields: error_code, error_msg.
- Python, run3 (`lab/go_to_goal.py`): printed "Nav2 is ready for use!", then one line per second of navigation time from "0 s: 3.33 m to go" to "14 s: 0.12 m to go", then "Goal succeeded!". End position (-1.961, -0.517), 0.04 m from the goal. The first line, "bt_navigator/get_state service not available, waiting...", is normal while the script connects.
- `waitUntilNav2Active()` defaults to localizer='amcl' and then waits for AMCL and an initial pose; with localizer='robot_localization' it skips the localizer checks and waits only for bt_navigator (robot_navigator.py source, `waitUntilNav2Active`). The loopback simulator replaces AMCL (README: it provides the map -> odom transform), so the script passes localizer='robot_localization'. Explain this plainly; it is the one non-obvious line.
- Stopping: Ctrl+C in the launch terminal. The ros2 command-line daemon keeps running in the background afterwards; `ros2 daemon stop` ends it (printed "The daemon has been stopped").
