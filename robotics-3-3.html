3.3 Installing ROS on Your Local Environment

Gerald Lê

01. Choosing your installation strategy

Setting up a robotics development environment is an important first milestone. ROS 2 is not a stand-alone operating system: it is a set of tools and libraries that runs on top of a host operating system, and each ROS 2 distribution requires a specific Ubuntu LTS release (other platforms may need a source build or containers).[1] Getting the host right is therefore the first step.

New engineers often run into installation problems because they do not know which platforms a release officially supports. Depending on whether your computer runs Ubuntu Linux, Microsoft Windows, or Apple macOS, your path to a working ROS 2 environment will look different: binary packages are only built for the Tier 1 platforms, and everything else means building from source or using a container.[2]

In this lesson, we walk through the installation for our target long-term support release: ROS 2 Lyrical Luth, released on May 22, 2026 and supported until May 2031.[3][4] We look at platform tiers, give the exact commands to install the packages, configure the shell environment, and diagnose common setup errors.

02. Platform support tiers and REP 2000

ROS 2 groups supported platforms (an operating system, a CPU architecture and a middleware) into three tiers.[5] Up to Kilted Kaiju, the target platforms for each release were listed in ROS Enhancement Proposal 2000 (REP 2000); from Lyrical Luth onward, REP 2000 no longer covers new releases and the platform list lives in each release's own documentation.[6][7] The tiers are:

  • Tier 1: Run through the unit test suite and other tests frequently, including continuous integration, nightly, packaging and performance jobs. Bugs on these platforms are prioritized and can delay a release.[5] For ROS 2 Lyrical Luth, Tier 1 platforms are Ubuntu 26.04 LTS (amd64 and arm64), which gets Debian packages and binary archives, and Windows 11 (amd64), which gets a binary archive.[7]
  • Tier 2: Get periodic CI builds and tests with public results; known errors are fixed on a best-effort basis.[5] For Lyrical, RHEL 10 (amd64) is Tier 2, with RPM packages and a binary archive available.[7][2]
  • Tier 3: The development team runs no tests; these platforms are listed because community reports say the release works.[5] For Lyrical, macOS, Ubuntu 24.04, Debian Trixie and others are Tier 3, and using Lyrical on any Tier 3 platform means building it from source.[7]

03. Native Ubuntu 26.04 installation step by step

Ubuntu Linux is the main home of ROS: Deb packages are the recommended way to install, because they pull in their dependencies automatically and update along with regular system updates.[2] Installing ROS 2 Lyrical Luth on Ubuntu 26.04 LTS follows four stages: set up your system (locale and repositories), install ROS, set up your environment, and test the installation.[8]

04. Setting up the UTF-8 locale and the ROS 2 apt repository

Step 1: Verify UTF-8 Locale. Make sure your system uses a locale that supports UTF-8.[8] Minimal environments, such as Docker containers, may use a minimal locale like POSIX; the ROS developers test with the en_US.UTF-8 settings below, but any UTF-8 locale should work.[8]

Check and generate a UTF-8 locale using the official commands:[8] 

locale  # check for UTF-8
sudo apt update && sudo apt install locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
locale  # verify settings

Step 2: Enable Universe and add the ROS 2 apt source. First make sure the Ubuntu Universe repository is enabled:[8] 

sudo apt install software-properties-common
sudo add-apt-repository universe

Next, install the ros2-apt-source package. It provides both the signing keys and the apt source configuration for the ROS repositories; apt uses the keys to check that downloaded packages really come from the ROS repositories. Because it is a package, the repository configuration also updates automatically when new versions are released. (Older guides downloaded a ros.key file by hand; the current documentation uses this package instead.)[8] 

sudo apt update && sudo apt install curl -y
export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb

Optionally, install the development tools you will need for building your own packages:[8] 

sudo apt update && sudo apt install ros-dev-tools

05. Desktop versus base installations

Once the repository is set up, refresh your package cache and make sure the system is up to date, because ROS packages are built on frequently updated Ubuntu systems:[8] 

sudo apt update
sudo apt upgrade

ROS 2 offers two main installation configurations:[8]

  • Desktop Install (Recommended): ROS, the RViz visualization tool, demos and tutorials. The desktop package extends ros_base with high-level packages such as visualization tools and demos.[8] For a workstation or laptop, install Desktop: 
    sudo apt install ros-lyrical-desktop
  • ROS-Base Install (Bare Bones): Communication libraries, message packages and command-line tools, with no GUI tools.[8] This suits a computer without a screen, such as a single-board computer mounted inside a mobile robot: 
    sudo apt install ros-lyrical-ros-base

The default middleware is Fast DDS; other RMW implementations can be installed as extra packages if your project needs them.[8]

06. Sourcing the environment: setup.bash

After the package installation completes, opening a fresh terminal and typing ros2 will typically fail with bash: ros2: command not found, because without sourcing the setup files you cannot access ROS commands or find ROS packages.[9]

The Debian packages install ROS 2 under /opt/ros/lyrical/. Why do you run source /opt/ros/lyrical/setup.bash? You run it so the ros2 command and its supporting libraries can be found in that terminal session.[9][8] If you use a different shell, replace .bash with .sh or .zsh.[8]

Sourcing setup.bash runs environment hooks that prepend the install folder to several shell environment variables:[10]

  • PATH: Prepends /opt/ros/lyrical/bin, so your shell can find the ros2 command-line tool.[10]
  • LD_LIBRARY_PATH: Prepends /opt/ros/lyrical/lib, so compiled C++ programs can find the ROS shared libraries at run time (on Linux).[10]
  • PYTHONPATH: Adds the ROS 2 Python package folder, so Python scripts can import rclpy and message definitions.[10]
  • AMENT_PREFIX_PATH: Adds the install prefix, which ROS tools use to find installed packages.[10]

Sourcing also sets variables such as ROS_DISTRO and ROS_VERSION.[9] Because sourcing only affects the current terminal session, you can append the command to your shell startup script (~/.bashrc), so every new terminal you open sources ROS 2 automatically:[9] 

echo "source /opt/ros/lyrical/setup.bash" >> ~/.bashrc

07. Windows installation: WSL 2 versus native

Windows users have two main ways to develop with ROS 2:

Option A: Windows Subsystem for Linux (WSL 2). WSL runs a real Ubuntu installation on Windows, and the ROS documentation notes that WSL improves the ROS 2 experience compared with a native Windows install because it runs on a Linux platform.[11] On Windows 11 (or Windows 10 build 19044 and later), WSL 2 can also run Linux GUI applications such as RViz2 and Turtlesim as normal desktop windows, with hardware-accelerated OpenGL once the matching GPU driver is installed.[12]

To set up WSL 2 with Ubuntu 26.04, open Windows PowerShell and run (use wsl --list --online to see the available names):[13] 

wsl --install Ubuntu-26.04

Once Ubuntu finishes installing, open the Ubuntu terminal and follow the native Ubuntu installation steps above.[11] If RViz crashes under WSL 2, forcing software rendering with export LIBGL_ALWAYS_SOFTWARE=true is a documented workaround.[14]

Option B: Native Windows 11 binary archive. For engineers who need tight integration with Windows software or Visual Studio C++ development, ROS 2 provides a pre-built Windows archive; only Windows 11 is supported.[15] It includes all ROS base packages but only some desktop packages. Dependencies come from conda-forge, managed with the pixi package manager, and compiling C++ packages needs Visual Studio Build Tools 2022.[15] The documented steps are to create a short folder such as C:\dev, install pixi, download the ros2-lyrical-*-windows-release-amd64.zip archive from the ROS 2 GitHub releases page, unpack it, install the dependencies, and source the environment in every new Command Prompt:[15] 

cd C:\dev\lyrical
pixi install
pixi run python preinstall_setup_windows.py
pixi shell
call C:\dev\lyrical\local_setup.bat

08. macOS strategies: Docker and virtual machines

For Lyrical Luth, macOS is a Tier 3 platform, so there are no official binaries and running Lyrical directly on macOS means building it from source.[7] The documentation also notes that ROS on macOS is community-supported and not recommended for new users.[1]

On a Mac, especially one with Apple silicon, two workflows avoid a source build:

  • Virtual machine: Install the arm64 edition of Ubuntu 26.04 LTS in a virtual machine (for example with UTM or Parallels). Ubuntu 26.04 on arm64 is a Tier 1 platform with Debian packages, so inside the VM you can install ros-lyrical-desktop with apt as usual.[7]
  • Docker Containers: Run an official ROS 2 desktop image; container solutions are the documented route for platforms without binaries:[2][16] 
    docker run -it osrf/ros:lyrical-desktop
    Showing graphical windows (RViz2 or Turtlesim) from a container on macOS needs extra display set-up, such as an X11 server or a VNC or browser-based desktop inside the container.

09. Post-installation verification: talker and listener

Once installation and sourcing are complete, check that both the C++ and Python client libraries work. If you installed ros-lyrical-desktop, open two separate terminal windows.[8]

In Terminal 1, start the pre-compiled C++ demo publisher node:[8] 

source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_cpp talker

The talker publishes a “Hello World” string with a counter on the chatter topic once per second:[17] 

[INFO] [1716400000.123456789] [talker]: Publishing: 'Hello World: 1'
[INFO] [1716400001.123456789] [talker]: Publishing: 'Hello World: 2'

In Terminal 2, start the Python demo subscriber node:[8] 

source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_py listener

The listener discovers the talker automatically and prints each message it hears:[18] 

[INFO] [1716400002.123456789] [listener]: I heard: [Hello World: 2]
[INFO] [1716400003.123456789] [listener]: I heard: [Hello World: 3]

If the talker says it is publishing and the listener says it hears those messages, both the C++ and Python APIs are working.[8] Press Ctrl+C in both windows to stop.

10. Essential developer utilities: rosdep and colcon

Before you begin creating custom packages in lesson 3.4, two developer tools must be installed:[19][20]

1. colcon (collective construction). colcon is the build tool for ROS 2 workspaces. It is an iteration on the earlier ROS build tools catkin_make, catkin_make_isolated, catkin_tools and ament_tools. It builds multi-package workspaces that mix build types such as ament_cmake, ament_python and plain cmake, and builds packages in parallel by default.[19] Install it with:[19] 

sudo apt install python3-colcon-common-extensions

2. rosdep (dependency resolver). Packages list their dependencies in package.xml, including non-ROS “system dependencies” on outside libraries. Installing every missing library by hand is tedious and error-prone.[20]

rosdep reads the dependency keys in the package.xml files of your workspace, looks them up in the central rosdistro index, and installs the matching packages through the system package manager (apt on Ubuntu). It currently works on Linux and macOS but not Windows.[20] Install and initialize it once on your system:[20] 

sudo apt install python3-rosdep
sudo rosdep init
rosdep update

11. Troubleshooting common setup errors

If your talker and listener test fails or commands behave unexpectedly, run through this diagnostic checklist:[14]

  • Command Not Found: List your ROS environment variables by running printenv | grep -i ROS. If ROS_DISTRO=lyrical and ROS_VERSION=2 do not appear, the setup file was not sourced in that terminal window.[9]
  • Listener Hears Nothing (Domain ID Mismatch): Nodes only communicate with nodes in the same domain, and the default domain is 0.[9][14] If one terminal ran export ROS_DOMAIN_ID=5 and the other did not, they cannot see each other. Run echo $ROS_DOMAIN_ID in both terminals to verify that they match.
  • Multicast Disabled or Blocked by a Firewall: DDS needs a network interface with multicast enabled, which is not always the case by default.[14] Test multicast with the ROS 2 tool:[14] 
    # In Terminal 1:
ros2 multicast receive
# In Terminal 2:
ros2 multicast send
    If no “Hello World!” message is received, your firewall may be blocking multicast. With Ubuntu's ufw firewall, allow multicast traffic (224.0.0.0/4) with:[14] 
    sudo ufw allow in proto udp to 224.0.0.0/4
sudo ufw allow in proto udp from 224.0.0.0/4
Try it
  1. Open a fresh terminal, run printenv | grep -i ROS, and note what environment variables are present. Sourced correctly, you should see ROS_DISTRO, ROS_VERSION, and AMENT_PREFIX_PATH.
  2. Open two terminals with matching ROS_DOMAIN_ID=42 and run the talker and listener. Verify that they discover each other. Then change the listener to ROS_DOMAIN_ID=43 and observe what happens.
  3. Run ros2 multicast receive in one terminal and ros2 multicast send in another to confirm that your local network and firewall permit DDS discovery broadcasts.
