3.3 Installing ROS on Your Local Environment

Gerald Lê

01. Choosing your installation strategy

Setting up a robotics development environment is a critical milestone in every roboticist's education. Because ROS 2 is middleware that coordinates processes, compiles custom C++ and Python packages, and interfaces with hardware buses, running it requires a properly configured host operating system.[1]

New engineers frequently encounter installation hurdles because they attempt to install software without understanding the underlying platform tiers. Depending on whether your primary personal computer runs Ubuntu Linux, Microsoft Windows, or Apple macOS, your path to a functioning ROS 2 environment will look slightly different.

In this lesson, we walk through the installation pipeline for our target long-term support release: ROS 2 Lyrical Luth, supported through 2031.[2] We examine platform tiers, provide the exact commands to install packages, configure essential shell environment variables, and diagnose common setup errors.

02. Platform support tiers and REP 2000

Open Robotics formalizes supported operating systems and architectures in ROS Enhancement Proposal 2000 (REP 2000).[3] Every ROS 2 distribution categorizes target operating systems into three distinct tiers:

  • Tier 1 (Fully Supported): Receives full automated Continuous Integration (CI) testing, pre-compiled binary Debian packages, release blockers for any build regressions, and official security maintenance. For ROS 2 Lyrical Luth, Tier 1 platforms are Ubuntu 26.04 LTS (on x86_64 and arm64 architectures) and Windows 11 (64-bit x86_64).[2][3]
  • Tier 2 (Source-Tested): Built and tested on continuous integration farms from source, but without guaranteed binary package mirror distributions (such as RHEL and CentOS Stream).[3]
  • Tier 3 (Community Maintained): No automated CI infrastructure; builds are maintained by external community volunteers. Apple macOS is a Tier 3 platform. Running ROS 2 on macOS requires virtual machines, Docker containers, or community Conda packaging.[3]

03. Native Ubuntu 26.04 installation step by step

Ubuntu Linux is the native home of ROS. Over 90% of open-source robot drivers, documentation examples, and research repositories assume an Ubuntu environment.[1] Installing ROS 2 Lyrical Luth on Ubuntu 26.04 LTS follows a four-stage pipeline: locale configuration, repository authentication, package installation, and environment initialization.[1]

04. Setting up UTF-8 locale and GPG keyrings

Step 1: Verify UTF-8 Locale. ROS 2 tools and Python 3 command-line utilities require an operating system locale that supports UTF-8 character encoding.[1] Bare server images, Docker containers, or minimal cloud virtual machines often default to an unconfigured POSIX or ASCII locale. Running ROS tools in a non-UTF-8 environment causes Python to throw fatal UnicodeDecodeError exceptions during node launch.

Verify and generate a proper UTF-8 locale using the official commands:[1] 

sudo apt update && sudo apt install -y locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8

Step 2: Enable Universe and Authorize GPG Keyring. Ensure the Ubuntu Universe software repository is enabled: 

sudo apt install -y software-properties-common curl
sudo add-apt-repository universe

Next, install the official Open Robotics GPG public key. The GPG key is used by the Linux APT package manager to cryptographically verify that downloaded software packages are authentic and have not been tampered with in transit:[1] 

sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg

Then add the official ROS 2 repository to your system sources list: 

echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

05. Desktop versus base installations

Once your package sources are updated, refresh your local package cache: 

sudo apt update

ROS 2 offers two primary installation configurations:[1]

  • Desktop Install (Recommended): Includes the complete ROS 2 core communication libraries, standard message definition packages, the Turtlesim 2D simulator, demos, perception headers, and the 3D graphical visualization environment rviz2. For a workstation or laptop, install Desktop: 
    sudo apt install -y ros-lyrical-desktop
  • ROS-Base Install: A stripped-down, headless installation containing only the core middleware, client libraries, and command-line tools, without any graphical windowing packages. Base is designed for resource-constrained onboard single-board computers (such as a Raspberry Pi 5 or NVIDIA Jetson mounted inside a mobile robot): 
    sudo apt install -y ros-lyrical-ros-base

06. Sourcing the environment: setup.bash

After the package installation completes, opening a fresh terminal and typing ros2 will result in a frustrating error: bash: ros2: command not found.

This happens because ROS 2 installs all its executable binaries, libraries, Python modules, and share directories into a self-contained root folder: /opt/ros/lyrical/. Why do you run source /opt/ros/lyrical/setup.bash? You run it so the ros2 command and its supporting libraries can be found in that terminal session.[4]

Sourcing setup.bash sets and modifies several critical shell environment variables:[4]

  • PATH: Prepends /opt/ros/lyrical/bin, allowing your shell to locate the ros2 CLI, compiler wrappers, and node executables.
  • LD_LIBRARY_PATH: Points the dynamic runtime linker to /opt/ros/lyrical/lib so compiled C++ nodes can link against shared DDS and client libraries.
  • PYTHONPATH: Adds ROS 2's site-packages so Python scripts can import rclpy and standard message definitions.
  • AMENT_PREFIX_PATH: Tells ROS package search tools where installed interfaces and plugin manifests reside.

Because sourcing only alters the current terminal session, you should append the command to your personal shell configuration file (~/.bashrc). Every new terminal you open will automatically source your ROS 2 environment: 

echo "source /opt/ros/lyrical/setup.bash" >> ~/.bashrc

07. Windows installation: WSL 2 versus native

Windows users have two viable pathways to develop with ROS 2:[5]

Option A: Windows Subsystem for Linux (WSL 2) (Strongly Recommended). WSL 2 runs an authentic Linux kernel in a lightweight utility virtual machine managed directly by Windows 11. Through WSLg (Windows Subsystem for Linux GUI), Linux graphical applications like RViz2 and Turtlesim render seamlessly as native desktop windows with full GPU hardware acceleration.

To set up WSL 2, open Windows PowerShell as Administrator and run: 

wsl --install -d Ubuntu-26.04

Once Ubuntu finishes installing, open the Ubuntu terminal prompt and follow the exact native Ubuntu installation steps detailed above.

Option B: Native Windows 11 Binary Archive. For engineers who require tight integration with proprietary Windows industrial software or Visual Studio 2022 C++ development, ROS 2 provides native Windows binary archives.[5] In modern releases, dependencies (including Python 3.12, CMake, OpenCV, and OpenSSL) are managed cleanly using the modern pixi cross-platform package manager. You download the official ROS 2 zip archive, unpack it to C:\ros2_lyrical, and source its batch environment: 

call C:\ros2_lyrical\local_setup.bat

08. macOS strategies: Docker and virtual machines

Under REP 2000, macOS is a Tier 3 platform. There are no pre-compiled .pkg or .dmg installers, and building the entire desktop suite from source requires overcoming non-trivial clang compiler differences.[3]

On Apple Silicon Macs (M1 through M4 chips), the two most reliable workflows are:

  • Virtualization with UTM or Parallels: Install an ARM64 edition of Ubuntu 26.04 LTS inside a virtual machine. UTM is a free, open-source hypervisor utilizing native Apple Hypervisor virtualization, providing near-native execution speed. Inside the ARM64 Ubuntu VM, install ros-lyrical-desktop via apt normally.
  • Docker Containers: Run the official Open Robotics container: 
    docker run -it --net=host osrf/ros:lyrical-desktop
    To display graphical windows (RViz2 or Turtlesim) on macOS, forward X11 display sockets via XQuartz or use modern VNC/web browser stream containers.

09. Post-installation verification: talker and listener

Once your installation and environment sourcing are complete, verify that both the C++ and Python client libraries are functioning correctly. Open two separate terminal windows.[1]

In Terminal 1, start the pre-compiled C++ demo publisher node: 

source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_cpp talker

The talker will begin broadcasting text strings over topic /chatter at 1 Hz: 

[INFO] [1716400000.123456789] [talker]: Publishing: 'Hello World: 1'
[INFO] [1716400001.123456789] [talker]: Publishing: 'Hello World: 2'

In Terminal 2, start the Python demo subscriber node: 

source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_py listener

The listener will immediately discover the talker via DDS multicast, establish a peer subscription, and print: 

[INFO] [1716400002.123456789] [listener]: I heard: [Hello World: 2]
[INFO] [1716400003.123456789] [listener]: I heard: [Hello World: 3]

If the listener prints each incoming message, your ROS 2 networking, C++ core, and Python bindings are fully operational. Press Ctrl+C in both windows to stop.

10. Essential developer utilities: rosdep and colcon

Before you begin creating custom packages in lesson 3.4, two critical developer tools must be installed:[6][7]

1. colcon (Collective Construction). colcon is the standard build tool used in ROS 2.[6] In ROS 1, developers used catkin_make. colcon is significantly more versatile: it builds multi-package workspaces containing arbitrary mixtures of C++ (CMake), Python (setuptools), and pure documentation packages in parallel. Install it with: 

sudo apt install -y python3-colcon-common-extensions

2. rosdep (Dependency Resolver). When you download an open-source ROS package from GitHub, it often depends on external Linux system libraries (such as Boost, Eigen, libusb, or OpenCV).[7] Manually reading package.xml and installing every missing library with apt is tedious and error-prone.

rosdep inspects all packages in your workspace, queries the official ROS package database, and automatically downloads and installs all missing system dependencies with a single command.[7] Initialize rosdep once on your system: 

sudo apt install -y python3-rosdep
sudo rosdep init
rosdep update

11. Troubleshooting common setup errors

If your talker and listener test fails or commands behave unexpectedly, run through this diagnostic checklist:[8]

  • Command Not Found: Verify your shell environment variables by running printenv | grep -i ROS. If ROS_DISTRO=lyrical and ROS_VERSION=2 do not appear, you forgot to source setup.bash in that terminal window.
  • Listener Hears Nothing (Domain ID Mismatch): Nodes only communicate within the same DDS domain. If one terminal ran export ROS_DOMAIN_ID=5 and the other terminal left it at default 0, they cannot see each other. Run echo $ROS_DOMAIN_ID in both terminals to verify that they match.
  • Firewall Blocking UDP Multicast: DDS peer discovery relies on UDP multicast traffic on the 224.0.0.0/4 subnet. If an aggressive operating system firewall (like Ubuntu UFW) blocks multicast, test it with ROS multicast diagnostic tools: 
    # In Terminal 1:
ros2 multicast receive
# In Terminal 2:
ros2 multicast send
    If no packet arrives, open the necessary firewall ports: 
    sudo ufw allow in proto udp to 224.0.0.0/4
sudo ufw allow in proto udp from 224.0.0.0/4
Try it
  1. Open a fresh terminal, run printenv | grep -i ROS, and note what environment variables are present. Sourced correctly, you should see ROS_DISTRO, ROS_VERSION, and AMENT_PREFIX_PATH.
  2. Open two terminals with matching ROS_DOMAIN_ID=42 and run the talker and listener. Verify that they discover each other. Then change the listener to ROS_DOMAIN_ID=43 and observe what happens.
  3. Run ros2 multicast receive in one terminal and ros2 multicast send in another to confirm that your local network and firewall permit DDS discovery broadcasts.
