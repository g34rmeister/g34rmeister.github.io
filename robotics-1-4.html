1.4 Preliminary Requirements

Gerald Lê

You do not need to be an expert in anything before starting this course. The free textbook Modern Robotics expects only first-year physics, some linear algebra, basic differential equations and “only basic programming skills.”[1] This lesson walks through what is worth having, why, and where to learn it for free. It starts with the one thing that is not optional: safety.

01. Safety first: before you touch a real robot

An industrial arm is strong, fast and does exactly what its program says, even if a person is in the way. The U.S. Occupational Safety and Health Administration (OSHA) describes real accidents in its Technical Manual. They include:[2]

  • Unexpected motion while programming: the worker did not know the program, could not see well, or used a pendant with no enabling device.
  • Entering the cell in automatic mode: a worker went into the robot’s space while it was running and was pinned against a post.
  • Power switched on during maintenance: a coworker turned the power back on because lockout/tagout was not done properly.
  • Cleaning a sensor in automatic mode: a worker cleaned a photobeam sensor while the robot was still in automatic.

OSHA lists the sources of these hazards as human programming errors, control errors, unauthorized access, mechanical failure, time pressure and power system failures.[2] Each case above maps to a habit you can build from day one: know the program, use the enabling device, lock out before servicing, and never enter the cell in automatic mode.

Three rules from OSHA are worth memorizing:[2]

  • Slow teach speed: while programming, the robot should move at “10 inches per second (250 mm/second) or less.”
  • Enabling device: typically a 3-position switch on the teach pendant that must be held in the center (ON) position for the robot to move while you program it.
  • Lockout/tagout: before servicing, hazardous energy must be controlled under OSHA rule 29 CFR 1910.147 (lockout/tagout) or 1910.333. You lock the power off and tag it so nobody can turn it back on while you work.

OSHA also says that anyone who programs, operates or maintains a robot should receive adequate safety training before being assigned, and that removing or engineering away a hazard is preferred over relying on rules and protective equipment.[2] The main international standard is ISO 10218, revised in 2025. The new edition makes functional safety requirements more explicit, absorbs the cobot guidance from ISO/TS 15066, and adds cybersecurity requirements as they relate to safety.[3] You will meet its collaborative modes in 1.3 Types of Robots.

02. Python

Python is widely used in robotics for scripting, testing and higher-level logic, and it is one of the two main languages used with ROS. ROS 2 provides rclpy, its Python client library, which lets you create nodes, publishers and subscriptions with ordinary Python types. The ROS 2 documentation favors Python where “it makes prototyping iterations faster.”[4]

The Universal Robots language URScript has Python-like syntax, but it is still a vendor language, not Python. It runs on the robot’s controller, not in a normal Python interpreter.

  • The Python Tutorial (python.org)

03. C++

C++ is the other main ROS language. Its client library, rclcpp, is the C++ interface for the same jobs: nodes, publishers and subscriptions. The ROS 2 documentation suggests that nodes where efficiency matters “might be better implemented in C++.” Both rclcpp and rclpy are built on a shared C library, rcl, so they behave the same way.[4]

The Arduino language is also based on C/C++,[5] so what you learn here carries straight over to the microcontroller lessons in Chapter 6.

  • LearnCpp.com

04. Vendor robot languages

Industrial arms are usually programmed in their maker’s own language: ABB uses RAPID, Comau PDL2, FANUC Karel, Kawasaki AS, KUKA KRL, Stäubli VAL3 and Yaskawa Inform. VAL, used on Unimate robots, was one of the first robot languages. With over 30 robot manufacturers, there are roughly as many languages, and that lack of standardization causes real challenges.[6]

The good news is that the ideas are shared. A typical first FANUC course covers the teach pendant, jogging (moving the arm by hand with buttons), frames, motion types, programs for handling material, input/output (I/O) signals, and backup and restore.[7] Once you understand points, frames and moves in one language, the next one is much easier. Lesson 2.3 Common Programming Languages compares them.

You can practice without a robot. Universal Robots provides an emulator, URSim, for testing programs offline.[8] Offline programming tools such as RoboDK do the same for many brands, as an alternative to programming on the teach pendant.[9]

05. Math

Modern Robotics lists its math prerequisites as linear algebra, including matrix operations, and basic linear ordinary differential equations.[1] In practice that means four topics:

  • Trigonometry: sines and cosines turn joint angles into positions.
  • Vectors and matrices: linear algebra is how robots describe positions, orientations and the motion of their joints.
  • Derivatives and integrals: calculus shows up in velocities and in control, for example the integral and derivative terms of a PID controller.
  • Basic differential equations: how a system changes over time, which you need for robot dynamics.

Worked example: a two-link arm. This is our own worked example, the standard first exercise in forward kinematics (working out where the tool is from the joint angles). Picture a flat arm with two links of length L1 and L2. The first joint is at angle θ1 from the x-axis, and the second joint bends by θ2 relative to the first link. The tip of the arm is at: 

x = L1·cos(θ1) + L2·cos(θ1 + θ2)
y = L1·sin(θ1) + L2·sin(θ1 + θ2)
φ = θ1 + θ2      (the direction the tip points)

Try it with L1 = L2 = 1 m, θ1 = 30° and θ2 = 60°. Then x = 0.866 + cos 90° = 0.866 m, and y = 0.5 + sin 90° = 1.5 m. In Python: 

from math import cos, sin, radians

L1, L2 = 1.0, 1.0
t1, t2 = radians(30), radians(60)
x = L1 * cos(t1) + L2 * cos(t1 + t2)
y = L1 * sin(t1) + L2 * sin(t1 + t2)
print(round(x, 3), round(y, 3))   # 0.866 1.5

This one example uses every topic above. Trigonometry gives the formula. With matrices, you get the same answer by multiplying a rotation and a translation for each link. Differentiating x and y with respect to time gives the arm’s velocity, which leads to a matrix called the Jacobian (a matrix mapping joint velocities to tool velocities). Lesson 1.6 Robot Anatomy and Coordinate Frames builds on this with joints, frames and kinematics.

Free resources:

  • Modern Robotics (Lynch & Park): the book’s preprint PDF and lecture videos are free. The six-course Coursera specialization (about 4 weeks each at about 5 hours a week) can be audited without paying; graded work costs a fee.[1][10]
  • MIT OpenCourseWare 18.01: Single Variable Calculus
  • MIT OpenCourseWare 18.06: Linear Algebra

06. Physics and electronics basics

Modern Robotics expects “freshman-level physics, including f = ma”: force equals mass times acceleration.[1] That is what tells you how hard a motor must push to speed up an arm. A related idea is torque, the turning effect of a force, which grows with the distance from the joint. You can reason from this that a load held far out on a stretched arm is harder on the joints than the same load held close in.

For electronics, start with Ohm’s law: voltage equals current times resistance (E = IR, often written V = IR).[11] From there you can learn how motors, encoders and switches connect to a controller. The course covers PWM and encoders in Chapter 6.

Electricity is also a safety topic. OSHA lists electrical hazards (arc flash and shock), hydraulic hazards including high-pressure cutting streams, whipping pneumatic hoses, and parts thrown when a tool fails. It also notes that electrically powered robots can be stopped or powered down more safely and faster than hydraulic or pneumatic ones.[2]

07. Linux, git and simulators

Linux: ROS 2 runs mainly on Ubuntu Linux. The newest release, ROS 2 Lyrical Luth (22 May 2026, supported until May 2031), has Ubuntu 26.04 and Windows 11 as its Tier 1 (best supported) platforms.[12] Getting comfortable with the command line, moving between folders, running commands and editing files, pays off quickly.

git: git tracks every change to your code so you can undo mistakes and share work. The book Pro Git is free to read online.[13]

Simulators: run a robot in simulation before you run a real one. Gazebo is the usual simulator for ROS, and each ROS 2 release has a matching Gazebo version. For new users, Gazebo recommends Ubuntu 24.04 with ROS 2 Jazzy and Gazebo Harmonic.[14]

For Universal Robots, URSim runs on Linux or as a virtual machine on Windows. When URSim runs on the same computer as ROS, the robot’s IP address is 127.0.0.1. One warning: the Linux installer may remove ROS packages, so install ROS after URSim.[8]

  • Software Carpentry: The Unix Shell, a beginner lesson on the command line.[15]
  • Pro Git (Chacon & Straub), free online

08. Networking basics

Robots rarely work alone. Industrial robots talk to PLCs (programmable logic controllers, the computers that run factory equipment), cameras and other machines over Ethernet, and ROS 2 nodes exchange messages over the network. Useful basics:

  • IP addresses and subnets: how devices on a network find each other; a robot controller and a PC usually need addresses on the same subnet to communicate.
  • TCP vs. UDP: TCP provides “a reliable, in-order, byte-stream service”;[16] UDP is lighter and faster but does not guarantee delivery, so packets can be lost.[17] ROS 2’s default middleware (connectivity software that lets distributed nodes communicate), DDS (Data Distribution Service), runs over UDP.[18]
  • Ports: a single device runs many services, each listening on its own port number. Modbus TCP, for example, uses port 502.[19]

Factory equipment uses industrial protocols on top of Ethernet:

  • Modbus TCP: Modbus was developed by Modicon in 1979 and became a de facto standard in manufacturing. The TCP/IP version dates from 1999, and the specification is free with no licensing fees.[19]
  • EtherNet/IP: an industrial protocol built on standard Ethernet and TCP/IP. It also uses UDP for real-time cyclic data, and its underlying protocol, CIP (Common Industrial Protocol), is supported by hundreds of vendors.[20]
  • PROFINET: another industrial Ethernet standard, maintained by PROFIBUS & PROFINET International.[21]
  • OPC UA: the OPC UA Robotics specification (OPC 40010-1) defines a shared information model for industrial and mobile robots, covering asset management and condition monitoring of arms, axes, motors, controllers and software. Version 1.02 was released in September 2025.[22]
  • Computer Networks: A Systems Approach (free online book)

09. Learning mentality

When robot code is wrong, the robot tells you right away: it drives into a wall, stalls, or grips too hard. That feedback is immediate and impersonal. The most useful mindset is to treat each failure as information, test, adjust and try again, rather than expecting to get it right the first time.

The same habit keeps you safe. Test new code in a simulator first, then on the real robot at slow teach speed, and only then at full speed.

10. Optional: assembly language

Assembly language is a low-level language in which each instruction corresponds closely to one machine instruction of a specific processor.[23] It is not a prerequisite for this course. Nothing in this course asks you to write assembly, and Modern Robotics needs only basic programming skills.[1]

The evidence points the same way. An engineering education paper by He, Zhang and Shen (2015) taught microcontrollers with about 30% assembly and 70% embedded C, keeping assembly for understanding machine code, instruction timing and the stack, and noted that industry prefers high-level languages such as embedded C.[24] A 2022 All About Circuits article pointed out that assembly ranked 30th in IEEE Spectrum’s 2022 job-posting ranking, while C and C++ ranked 6th and 7th. It argued that the strongest reason to learn assembly is to understand what the processor actually does, and that there is “no one-size-fits-all answer.”[25]

So treat assembly as enrichment. Knowing what it looks like helps you reason about registers, memory, timing and interrupts, which matters when code has to be fast and predictable, such as reading an encoder inside an interrupt or generating precise PWM timing. You would normally write that code in C or C++, though.

  • Nand2Tetris: build a computer from logic gates up to assembly and beyond

11. Careers and a learning path

Robots need people to program and maintain them. The U.S. Bureau of Labor Statistics (BLS) covers this work in its Occupational Outlook Handbook under industrial machinery mechanics, maintenance workers and millwrights, with current job counts, median pay and a ten-year growth projection; check that page for the latest figures.[26]

For industrial roles, vendor training counts. FANUC America, for example, runs its own training courses with recommended paths in programming, vision, safety and more.[27] One example entry course, FANUC HandlingTool Operation and Programming at Kent State, runs 32 hours with 24 lab exercises, has no prerequisites, and leads to the FANUC Robotics CERT I credential.[7] Universal Robots Academy offers free e-learning for its e-Series robots, including an 8-module Core Track that simulates setting up and programming a complete pick-and-place application.[28] The Association for Advancing Automation (A3) also certifies robot integrator companies, and offers individual credentials such as Certified Motion Control Professional.[29]

A sensible order for an undergraduate, based on the sections above:

  1. Python, plus the Linux command line and git.
  2. A simulator: URSim, Gazebo or RoboDK.
  3. The math, through Modern Robotics.
  4. A vendor course (such as FANUC CERT I or UR Academy) if you are aiming at industry, or ROS 2 projects if you are aiming at research.
Try it
  1. Write a short Python or C++ program that converts a distance in centimeters to inches. If you can do this comfortably, you have enough programming to start.
  2. Change the two-link example to L1 = 0.5 m, L2 = 0.3 m, θ1 = 90° and θ2 = −90°. Work out x and y by hand first, then check with the code.
  3. Look up your computer’s IP address and subnet mask, and work out which other addresses would be on the same subnet. If you install URSim, ping 127.0.0.1 and explain why it answers.
  4. For each OSHA accident in section 01, write down the one habit that would have prevented it.
