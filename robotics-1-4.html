      1.4 Preliminary Requirements

      Gerald Lê
      Chapter 1, lesson 4 of 7 ← Previous: 1.3 Types of Robots Next: 1.5 Common Applications of Robotics →
      Start here

      This lesson lists what is useful to know before the rest of the course, and safety comes first. You do not need to master any of it before you begin. The course teaches what it needs as it goes. The safety rules matter most because real robot arms are strong and fast. On a first read, skim the math, networking, and assembly sections and come back to them when a later lesson asks.

      • You will learn the three essential safety rules for working near an industrial robot arm.
      • You will learn where Python, C++, and vendor languages fit into robotics programming.
      • You will learn how basic math and physics connect to the motion of a two-link robot arm.
      • You will learn how to choose a practical learning path using simulators and free tools.

      You do not need to be an expert in anything before starting this course. Each section below explains why a skill helps and where this course teaches it. The free textbook Modern Robotics expects only first-year physics, some linear algebra, basic differential equations and “only basic programming skills.”[1] Those advanced subjects are for later textbook chapters. For this course, school algebra is enough to start. This lesson walks through what is worth having, why, and where to learn it for free. It starts with the one thing that is not optional: safety.

      01. Safety first: before you touch a real robot

      Before you write a single line of robot code, you need to know how to stay safe around a real machine. An industrial arm is strong, fast, and follows its program blindly, even if a person is in the way. Learning a few safety habits on day one protects you when you move from a screen to a real robot cell.

      In the United States, the Occupational Safety and Health Administration (OSHA) tracks workplace safety and publishes rules for factories. Its Technical Manual describes real robot accidents so new programmers know what can go wrong:[2]

      • Unexpected motion while programming: the worker did not know the program, could not see well, or used a pendant with no enabling device.
      • Entering the cell in automatic mode: a worker went into the robot’s space while it was running and was pinned against a post.
      • Power switched on during maintenance: a coworker turned the power back on because lockout/tagout was not done properly.
      • Cleaning a sensor in automatic mode: a worker cleaned a photobeam sensor while the robot was still in automatic.

      OSHA lists six sources for these hazards. They are human programming errors, control errors, unauthorized access, mechanical failure, time pressure, and power system failures.[2] Each case above maps to a habit you can build from day one. Know the program, use the enabling device, lock out before servicing, and never enter the cell in automatic mode.

      Before you work near a real robot, three rules from OSHA are worth memorizing:[2]

      • Slow teach speed: while programming, the robot should move at “10 inches per second (250 mm/second) or less.”
      • Enabling device: typically a 3-position switch on the teach pendant that must be held in the center (ON) position for the robot to move while you program it.
      • Lockout/tagout: before servicing, hazardous energy must be controlled under OSHA rule 29 CFR 1910.147 (lockout/tagout) or 1910.333. You lock the power off and tag it so nobody can turn it back on while you work.

      In plain words: the teach pendant is the handheld unit you use to jog, teach, and test the robot (lesson 1.7 shows it in a full cell). While you teach, the robot moves slowly. It can move only while you hold the enabling switch in its center position. Before you service the robot, its power is locked off and tagged.

      OSHA also says that anyone who programs, operates, or maintains a robot should receive adequate safety training before being assigned. It adds that removing or engineering away a hazard is preferred over relying on rules and protective equipment.[2]

      Outside the United States, factories follow ISO 10218. It is the main international standard for industrial robot safety from the International Organization for Standardization (ISO). It covers functional safety requirements, collaborative robot (cobot) guidance, and cybersecurity requirements as they relate to safety.[3] Its collaborative modes were introduced in 1.3 Types of Robots.

      For the curious: ISO 10218 edition history and ISO/TS 15066

      ISO 10218 was revised in 2025. The new edition makes functional safety requirements more explicit, absorbs the cobot guidance from ISO/TS 15066, and adds cybersecurity requirements as they relate to safety.[3]

      02. Python for quick scripting and testing

      Python is often the first programming language you use with a robot. Suppose you want an arm or mobile robot to test a new motion or task. With Python, you can write a short script, run it right away, and adjust it quickly.

      Python is widely used in robotics for scripting, testing, and higher-level logic. It is also one of the two main languages used with the Robot Operating System (ROS). You will meet this free robot software in Chapter 4.

      ROS 2 provides rclpy, its Python client library (the software tools that let Python talk to ROS). It lets you create nodes, publishers, and subscriptions with ordinary Python types. You will meet nodes and publishers in Chapter 4. For now, you only need to know that Python is used. The ROS 2 documentation favors Python where “it makes prototyping iterations faster.”[4]

      The Universal Robots language URScript has Python-like syntax. Even so, it is still a vendor language (the robot maker’s own programming language), not Python. It runs on the robot’s controller, not in a normal Python interpreter (the program that runs Python code).

      • The Python Tutorial (python.org)

      03. C++ for speed and microcontrollers

      Python is quick to write, but sometimes a robot needs code that runs as fast as possible. Think of reading sensors and updating motors many times per second. That is where C++ fits, and it also connects directly to small electronics boards.

      C++ is the other main ROS language. Its client library, rclcpp, is the C++ interface for the same jobs: nodes, publishers, and subscriptions. The ROS 2 documentation suggests that nodes where efficiency matters “might be better implemented in C++.” Both rclcpp and rclpy are built on a shared C library, rcl, so they behave the same way.[4]

      The Arduino language is also based on C/C++.[5] An Arduino is a small, cheap programmable board used for robot electronics, taught in lesson 6.1. What you learn in C++ carries straight over to the microcontroller lessons in Chapter 6.

      • LearnCpp.com

      04. Vendor robot languages

      When you work with a real factory arm, you usually do not program it in Python or C++. Most robot makers ship their own programming language built for their hardware. The good news is that the core ideas stay the same across brands, so learning one makes the next much easier.

      Industrial arms are usually programmed in their maker’s own language. For example, ABB uses RAPID, FANUC uses Karel, and KUKA uses KRL. With over 30 robot manufacturers, there are roughly as many languages, and none of them is a common standard.[6]

      A typical first FANUC course covers the teach pendant and jogging (moving the arm by hand with buttons). It also covers frames, motion types, material handling programs, input/output (I/O) signals, and backup and restore.[7] You will meet coordinate frames in lesson 1.6 and motion types throughout Chapter 2. They are standard first topics for every robot programmer. Once you understand points, frames, and moves in one language, the next one is much easier. Lesson 2.3 Common Programming Languages compares them.

      You can practice without a robot. Universal Robots provides an emulator, URSim, for testing programs offline.[8] Offline programming tools such as RoboDK do the same for many brands, as an alternative to programming on the teach pendant.[9]

      For the curious: more vendor languages and early robot languages

      Across manufacturers, ABB uses RAPID, Comau uses PDL2, FANUC uses Karel, Kawasaki uses AS, KUKA uses KRL, Stäubli uses VAL3, and Yaskawa uses Inform. VAL, used on Unimate robots, was one of the first robot languages.[6]

      05. Math: turning joint angles into positions

      Optional on first reading. This section previews the math behind robot arm motion. You can safely skim the formulas for now, and lesson 6.10 returns to them when you need them.

      You do not need advanced math to start this course. Still, a little math explains how a robot arm knows where its tip lands in space. When you bend your shoulder and elbow, your hand moves to a new spot. A robot uses joint angles and link lengths to calculate that exact spot.

      You do not need to use all of this at once. This list explains what each topic is for, and matrices and calculus are not needed for week one. Modern Robotics lists its math prerequisites as linear algebra, including matrix operations, and basic linear ordinary differential equations.[1] In practice, that means four topics:

      • Trigonometry: sines and cosines turn joint angles into positions.
      • Vectors and matrices: linear algebra is how robots describe positions, orientations, and the motion of their joints.
      • Derivatives and integrals: calculus shows up in velocities and in control, for example the integral and derivative terms of a proportional-integral-derivative (PID) controller.
      • Basic differential equations: how a system changes over time, which you need for robot dynamics.

      Worked example: a two-link arm. This is our own worked example. It is the standard first exercise in forward kinematics (working out where the tool is from the joint angles). Picture a flat arm with two links of length L1 and L2. Think of your arm lying flat on a table. Your upper arm and forearm are the two links, while your shoulder and elbow are the joints. The first joint is at angle θ1 from the x-axis. The second joint bends by θ2 relative to the first link. The tip of the arm is at: 

      x = L1·cos(θ1) + L2·cos(θ1 + θ2)
y = L1·sin(θ1) + L2·sin(θ1 + θ2)
φ = θ1 + θ2      (the direction the tip points)

      In plain words: L1 and L2 are the lengths of the two arm sections. The angles θ1 and θ2 describe how much each joint turns. The letters x and y mark where the tip lands on the table. With both links at 1 m, bending 30° then 60° places the tip at x = 0.866 m and y = 1.5 m.

      Try it with L1 = L2 = 1 m, θ1 = 30° and θ2 = 60°. Then x = 0.866 + cos 90° = 0.866 m, and y = 0.5 + sin 90° = 1.5 m. In Python: 

      from math import cos, sin, radians

L1, L2 = 1.0, 1.0
t1, t2 = radians(30), radians(60)
x = L1 * cos(t1) + L2 * cos(t1 + t2)
y = L1 * sin(t1) + L2 * sin(t1 + t2)
print(round(x, 3), round(y, 3))   # 0.866 1.5

      This one example uses every topic above. Trigonometry gives the formula. With matrices, you get the same answer by multiplying a rotation and a translation for each link. Differentiating x and y with respect to time gives the arm’s velocity. That leads to a matrix called the Jacobian, which maps joint velocities to tool velocities.

      This worked example is a preview. Lesson 1.6 Robot Anatomy and Coordinate Frames builds on it with joints, frames, and kinematics step by step. Lesson 6.10 covers the Jacobian matrix in full detail.

      06. Physics and electronics basics

      A little physics explains why a robot motor strains when you reach far out or speed up too fast. Basic electricity explains how sensors, switches, and motors connect to a controller. You will use both ideas when wiring real robot parts and choosing safe speeds.

      Modern Robotics expects “freshman-level physics, including f = ma”: force equals mass times acceleration.[1] In words, the heavier an arm and the faster you want it to speed up, the harder its motor must push.

      A related idea is torque, the turning effect of a force, which grows with the distance from the joint. Think of using a wrench, where a longer handle makes it easier to turn a tight bolt. Holding a load far out on a stretched arm strains the joints more than holding it close in.

      For electronics, start with Ohm’s law: voltage equals current times resistance (E = IR, often written V = IR).[11] From there, you can learn how motors, encoders, and switches connect to a controller. The course covers pulse width modulation (PWM) and encoders in Chapter 6.

      In plain words: think of electricity like water flowing in a pipe. Voltage is the pressure pushing the water, current is the rate of flow, and resistance is how narrow the pipe is.

      Electricity is also a safety topic. OSHA lists electrical hazards (arc flash and shock), hydraulic hazards including high-pressure cutting streams, whipping pneumatic hoses, and parts thrown when a tool fails. It also notes that electrically powered robots can be stopped or powered down more safely and faster than hydraulic or pneumatic ones.[2]

      07. Linux, git and simulators

      Real robots cost a lot and can break equipment if your program has a mistake. Instead of testing straight on hardware, you test code on a virtual robot in a simulator first. That is why robot programmers spend most of their time in Linux, tracking code with git, and running simulators.

      Linux: ROS 2 runs mainly on Ubuntu Linux. Linux is an operating system like Windows or macOS. The command line means typing text commands instead of clicking icons.

      You do not need to install anything today. Lesson 4.3 provides a step-by-step setup guide for ROS 2 Lyrical Luth on Ubuntu 26.04.[12] Getting comfortable with the command line (moving between folders, running commands, and editing files) pays off quickly.

      git: git tracks every change to your code so you can undo mistakes and share work. The book Pro Git is free to read online.[13]

      Simulators: run a robot in simulation before you run a real one. Gazebo is the usual simulator for ROS, and each ROS 2 release has a matching Gazebo version. For new users, Gazebo recommends Ubuntu 24.04 with ROS 2 Jazzy and Gazebo Harmonic.[14] This course installs ROS 2 Lyrical on Ubuntu 26.04 (4.3). If you follow the course, use the Lyrical row of the table below. You will use Gazebo in lesson 4.5.

      ROS 2 releaseGazebo version
      Humble (long-term support)Fortress
      Jazzy (long-term support)Harmonic
      KiltedIonic
      Lyrical (long-term support)Jetty

      For Universal Robots, the free simulator URSim runs on Linux or as a virtual machine on Windows. When URSim runs on the same computer as ROS, the robot’s Internet Protocol (IP) address is 127.0.0.1 (a special address that means your own computer). One warning: the Linux installer may remove ROS packages, so install ROS after URSim.[8]

      • Software Carpentry: The Unix Shell, a beginner lesson on the command line.[15]
      • Pro Git (Chacon & Straub), free online
      For the curious: ROS 2 Lyrical Luth release dates and platform support

      The newest release, ROS 2 Lyrical Luth, came out on 22 May 2026 and is supported until May 2031. It has Ubuntu 26.04 and Windows 11 as its Tier 1 (best supported) platforms.[12]

      08. Networking basics

      Optional on first reading. This section introduces how robots talk to other factory equipment over a network. You can skim these details now, and lesson 8.2 covers industrial network protocols in depth.

      Robots rarely work alone in a cell. An industrial arm often waits for a camera to spot a part. It might also wait for a factory controller to signal when to move. Those machines talk to one another over a network, and a few basic ideas explain how messages travel between them.

      Industrial robots talk to programmable logic controllers (PLCs, the computers that run factory equipment), cameras, and other machines over Ethernet. ROS 2 nodes also exchange messages over the network. Useful basics:

      • IP addresses and subnets: these are how devices on a network find each other. A robot controller and a personal computer (PC) usually need addresses on the same subnet to communicate.
      • TCP vs. UDP: Transmission Control Protocol (TCP) provides “a reliable, in-order, byte-stream service.”[16] User Datagram Protocol (UDP) is lighter and faster, though it does not guarantee delivery, so packets can be lost.[17] ROS 2’s default middleware (connectivity software that lets distributed nodes communicate) is Data Distribution Service (DDS), and it runs over UDP.[18]
      • Ports: a single device runs many services, each listening on its own port number. Modbus TCP, for example, uses port 502.[19]

      In plain words: TCP is like registered mail where the sender gets a receipt for every letter. UDP is like a postcard that sends fast without checking if it arrived.

      Factory equipment uses industrial protocols on top of Ethernet:

      • Modbus TCP: a widely used manufacturing protocol whose specification is free with no licensing fees.[19]
      • EtherNet/IP: an industrial protocol built on standard Ethernet and TCP/IP. It also uses UDP for real-time cyclic data.[20]
      • PROFINET: another industrial Ethernet standard, maintained by PROFIBUS & PROFINET International.[21]
      • OPC Unified Architecture (OPC UA): defines a shared information model for industrial and mobile robots. It covers asset management and condition monitoring of arms, axes, motors, controllers, and software.[22]
      • Computer Networks: A Systems Approach (free online book)
      For the curious: protocol history, CIP, and OPC UA specification details

      Modbus was developed by Modicon in 1979 and became a de facto standard in manufacturing. Its TCP/IP version dates from 1999.[19]

      EtherNet/IP relies on an underlying protocol called Common Industrial Protocol (CIP), which is supported by hundreds of vendors.[20]

      The OPC UA Robotics specification is numbered OPC 40010-1, and Version 1.02 was released in September 2025.[22]

      09. Learning mentality: test, adjust, and try again

      Every programmer writes bugs at first, and that is normal in robotics. Unlike a quiet software crash, a bug in robot code shows up right in front of you in the physical world. Treating each mistake as useful feedback keeps both you and the robot safe.

      When robot code is wrong, the robot tells you right away. It drives into a wall, stalls, or grips too hard. That feedback is immediate and impersonal. Treat each failure as information: test, adjust, and try again, rather than expecting to get it right the first time.

      The same habit keeps you safe. Test new code in a simulator first. Next, test it on the real robot at slow teach speed, and only then at full speed.

      10. Optional: do you need assembly language?

      You might wonder if robotics requires writing low-level assembly language. It does not, and nothing in this course asks you to write it. You can safely skip this section on a first reading and treat it as optional background.

      Assembly language is a low-level language in which each instruction corresponds closely to one machine instruction of a specific processor.[23] It is not a prerequisite for this course. Modern Robotics also needs only basic programming skills.[1] Most industry and microcontroller work relies on high-level languages like C and C++ instead.[24][25]

      Treat assembly as enrichment. Knowing what it looks like helps you reason about registers, memory, timing, and interrupts. That matters when code has to be fast and predictable. Examples include reading an encoder inside an interrupt or generating precise PWM timing. Even then, you would normally write that code in C or C++.

      • Nand2Tetris: build a computer from logic gates up to assembly and beyond
      For the curious: teaching studies and job-ranking numbers for assembly

      An engineering education paper by He, Zhang, and Shen (2015) taught microcontrollers with about 30% assembly and 70% embedded C. It kept assembly for understanding machine code, instruction timing, and the stack, and noted that industry prefers high-level languages such as embedded C.[24]

      A 2022 All About Circuits article pointed out that assembly ranked 30th in IEEE Spectrum’s 2022 job-posting ranking (published by the Institute of Electrical and Electronics Engineers), while C and C++ ranked 6th and 7th. It argued that the strongest reason to learn assembly is to understand what the processor actually does, and that there is “no one-size-fits-all answer.”[25]

      11. Careers and a learning path

      Knowing what tools exist is helpful, but knowing what order to learn them in saves time. Whether you aim to program factory arms or work on research projects, you can start on your own computer with free tools. Here is how training programs and a step-by-step learning path fit together.

      Robots need people to program and maintain them. The U.S. Bureau of Labor Statistics (BLS) covers this work in its Occupational Outlook Handbook under industrial machinery mechanics, maintenance workers, and millwrights. That entry gives current job counts, median pay, and a ten-year growth projection. Check that page for the latest figures.[26]

      For industrial roles, vendor training counts. FANUC America runs its own training courses with recommended paths in programming, vision, safety, and more.[27] Entry courses can lead to credentials such as FANUC Robotics CERT I.[7]

      Universal Robots (UR) Academy offers free e-learning for its e-Series robots. That includes an 8-module Core Track that simulates setting up and programming a complete pick-and-place application.[28] The Association for Advancing Automation (A3) also certifies robot integrator companies and offers individual credentials such as Certified Motion Control Professional.[29]

      Here is a sensible learning order for an undergraduate, based on the sections above:

      1. Python, plus the Linux command line and git.
      2. A simulator: URSim, Gazebo, or RoboDK.
      3. The math, through Modern Robotics.
      4. A vendor course (such as FANUC CERT I or UR Academy) if you are aiming at industry, or ROS 2 projects if you are aiming at research.
      For the curious: an example FANUC entry course at Kent State

      One example entry course is FANUC HandlingTool Operation and Programming at Kent State University. It runs 32 hours with 24 lab exercises, has no prerequisites, and leads to the FANUC Robotics CERT I credential.[7]

      Try it
      1. Write a short Python or C++ program that converts a distance in centimeters to inches. If you can do this comfortably, you have enough programming to start.
      2. Change the two-link example to L1 = 0.5 m, L2 = 0.3 m, θ1 = 90° and θ2 = −90°. Work out x and y by hand first, then check with the code.
      3. Look up your computer’s IP address and subnet mask, and work out which other addresses would be on the same subnet. If you install URSim, ping 127.0.0.1 and explain why it answers.
      4. For each OSHA accident in section 01, write down the one habit that would have prevented it.
