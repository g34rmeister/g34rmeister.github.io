      9.5 Calibration, Backups and Recovery

      Gerald Lê
      Chapter 9, lesson 5 of 6 ← Previous: 9.4 Electrical and I/O Faults Next: 9.6 Lab: Check a Robot's State from Python →

      01. Revolution counters and axis synchronization

      A robot only knows where its joints are if its position sensors and its stored calibration data agree with the real arm (1.6 Robot Anatomy and Coordinate Frames covers the joints). After some repairs that agreement is lost and has to be restored. This lesson uses ABB's and Universal Robots' procedures as examples; always follow the manual for your own robot.

      On ABB robots, each motor has a resolver that measures its angle, and the controller also counts whole motor turns (the revolution counter).

      Updating the revolution counter is necessary when calibration values have been entered manually or an axis revolution counter must be updated against the synchronization position.[1]

      The first step when updating the revolution counter is to move the robot and positioner axes to their respective zero positions at the synchronization marking.[1]

      Then update the counters on the FlexPendant: in the service window, tap Calibration, select the mechanical unit, tap Revolution Counters, and tap Update Rev. Counters.[1]

      02. Resolver calibration and fine calibration

      Updating the revolution counter is different from changing the calibration values themselves.

      Manual setting of calibration values is only necessary if the robot system has lost its resolver calibration values.[1]

      Cells can also have external axes, such as a turntable or a linear track.

      Fine calibration is necessary when an external axis has no calibration values, but should not be used on an axis that already has them.[1]

      03. Tool center point and load data

      After a tool is changed or repaired, its tool center point (TCP) and load data must be checked (see 2.5 End-of-Arm Tooling and I/O).

      A TCP is taught by touching a fixed point from several directions. Defining a TCP uses a 5-point method when the robot weaves during welding; without weaving, a 4-point method is sufficient.[1]

      The tool data also includes the load: its mass and center of gravity.

      A correct tool load in the tool data matters most when collision detection is used.[1] 9.3 showed the same point for UR: wrong payload settings are a common cause of protective stops.

      04. Joint replacement and type validation

      On a UR robot, a failed joint can be replaced as a whole unit.

      The replacement must match the robot model. Replacing robot joints with joints from a different robot model can trigger error C364A1, which indicates a robot type disagreement in the joints when attempting to release the brakes.[2]

      UR's joint validation procedure is a service-technician task. Before joint validation, power on the robot until a yellow indicator shows the Idle state in PolyScope or Locked in PolyScope X.[2] The rest of the procedure is in the service manual and is not covered here.

      05. Workspace recalibration and program correction

      A replaced joint also changes the arm's geometry slightly, so old programs may miss their positions.

      Dual Robot Calibration calibrates the robot across its full workspace so it can resume production after joint replacement without modifying program waypoints.[3]

      Each new UR robot is Dual Robot Calibrated as part of final assembly. Repeating it after a repair needs two robots of the same size and generation, plus UR’s Dual Robot Calibration tooling.[3] If you do not have a second matching robot, that leaves the other option: correcting the program.

      Program Correction by Key Waypoints adjusts waypoints when transferring programs between robots or making programs work following joint replacements.[3]

      Program Correction by Key Waypoints supports only fixed waypoints and does not support Move nodes configured with Use Joint Angles.[3] Those moves have to be checked and re-taught by hand.

      06. Controller backups and storage recovery

      Programs, settings and calibration data live on the controller's storage card.

      The flashcard, USB drive or SD card is the robot's hard drive, and it must never be removed while power is on, to avoid corrupting the operating system.[4]

      Back up the old storage media before replacing it, because all files, including joint calibration data, can be permanently lost.[4] Reflashing an SD card or USB stick deletes all robot programs and calibration files, so make a full backup before reinstalling the image.[4]

      Universal Robots magic files automatically back up data to a USB stick, copying programs, installation files, and configuration files.[3]

      Running a magic file takes four steps:[3]

      1. Download the magic file from UR’s support site and save it to the root folder of a USB stick.
      2. Insert the stick into the USB slot in the control box. A red !USB! sign appears on the screen; do not remove the stick.
      3. Wait for the green USB sign. Large files, such as the history log, can take up to two minutes.
      4. When the last magic file has finished, remove the stick. The backup is in a folder named with the robot’s serial number.

      If several magic files are on the stick, they run one after another, and each gets its own numbered folder. If nothing happens when you insert the stick, check the security settings: from PolyScope 5.11 on, running magic files can be turned off there.[3] Whatever method you use, back up the program and installation files before every software update.[3]

      Manual backup of the SD card datafs partition requires copying the programs directory, root serial and log files, and the urcontrol calibration files.[3] The datafs partition contains the programs/ directory (holding all application and installation scripts), root/ur-serial, root/log_history.txt, and the .urcontrol/ configuration directory containing calibration.conf and calibration.log.[3]

      If internal storage is damaged, a bootable storage device lets you boot the control box with a new robot image and recover.[3]

      A PolyScope system backup requires a USB drive with at least 4 GB capacity and can be restored if the software must be downgraded below version 5.8.[3]

      07. Check your understanding

      • What is the difference between a 4-point and a 5-point method when defining a tool center point (TCP), and when does a correct tool load matter most?
        Show answer

        A 5-point method is used when the robot weaves during welding; without weaving, a 4-point method is sufficient. A correct tool load in the tool data matters most when collision detection is used. (Section 03)

      • What error code appears when a UR joint from a different robot model is fitted, and why must the storage card be backed up before it is replaced or reflashed?
        Show answer

        Error C364A1 appears; it indicates a robot type disagreement in the joints when the brakes are released. The storage card must be backed up first because all files, including joint calibration data, can be permanently lost, and reflashing deletes all robot programs and calibration files. (Sections 04 and 06)

      • What data must be copied during a manual backup of the SD card datafs partition, and why must storage media never be removed while controller power is on?
        Show answer

        A manual backup of the datafs partition requires copying the programs directory, the root serial and log files, and the urcontrol calibration files. The media must never be removed while power is on because the flashcard, USB drive or SD card is the robot’s hard drive, and removing it could corrupt the operating system. (Section 06)
