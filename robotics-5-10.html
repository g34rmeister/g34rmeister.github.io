5.10 Kinematics of a 2-Link Arm

Gerald Lê

01. From the idea to the full math

Lesson 1.6 introduced forward and inverse kinematics with a small planar arm: two revolute joints, a first link L1 = 0.4 m long and a second link L2 = 0.3 m long. This lesson works through the complete math for the same arm: where the formulas come from, which targets it can reach, how to write inverse kinematics code that does not break at the edges, and how the Jacobian predicts the poses where the arm loses a direction of motion.

Every number here uses the 1.6 arm, so you can check each answer in the lesson 1.6 simulator: its sliders set θ1 and θ2, and tapping inside its ring places the tool and solves inverse kinematics.

The conventions are the same as in the simulator:

  • Frame: the shoulder joint is at the origin, x points right, y points up, and positive angles turn counter-clockwise.
  • θ1: the angle of link 1, measured from the x-axis.
  • θ2: the angle of link 2 relative to link 1. θ2 = 0 means the arm is straight. θ2 = ±180° means link 2 is folded back on top of link 1.
  • Units: lengths in meters. The formulas use radians, but the worked answers are given in degrees, to match the simulator's readout.

02. Forward kinematics: adding two rotating vectors

The tool position is the sum of two vectors. Link 1 points along the angle θ1, so the elbow is at (L1 cos θ1, L1 sin θ1). Link 2 is mounted on link 1, so its direction is θ1 plus its own joint angle: joint angles add along a serial chain. That gives the forward kinematics (FK): 

x = L1·cos θ1 + L2·cos(θ1 + θ2)
y = L1·sin θ1 + L2·sin(θ1 + θ2)
tool angle φ = θ1 + θ2

The open-source PythonRobotics collection uses exactly these two steps in its two-joint arm demo. It computes the elbow as the shoulder plus (l1 cos θ1, l1 sin θ1), then the wrist as the elbow plus (l2 cos(θ1 + θ2), l2 sin(θ1 + θ2)). The file names Peter Corke's textbook Robotics, Vision and Control as its reference.[1]

Forward kinematics always has exactly one answer. Lesson 1.6 worked the example θ1 = 30°, θ2 = 45°, which puts the tool at (0.4241, 0.4898) m, the same point the simulator's readout shows.

03. The workspace is a ring

Before solving inverse kinematics, it helps to know which points the arm can reach at all. Draw the triangle formed by the shoulder, the elbow and the tool. Its sides are L1, L2 and r, where r = √(x² + y²) is the distance from the shoulder to the tool. A triangle can exist only if each side is no longer than the sum of the other two (the triangle inequality). For the side r, that means: 

|L1 − L2| ≤ r ≤ L1 + L2
0.1 m ≤ r ≤ 0.7 m      (for L1 = 0.4 m, L2 = 0.3 m)

So the reachable workspace is a ring (in geometry, an annulus): a disk of radius 0.7 m with a hole of radius 0.1 m cut out of the middle. The simulator draws both circles. The number of inverse kinematics solutions depends on where the target sits relative to that ring:[2]

  • Strictly inside the ring: two solutions. The triangle can be flipped across the line from shoulder to tool, giving an elbow on either side.
  • On the outer circle (r = 0.7 m): one solution, the arm fully stretched (θ2 = 0). The triangle has collapsed into a straight line, so there is nothing to flip.
  • On the inner circle (r = 0.1 m): one solution, the arm fully folded (θ2 = 180°). The triangle has collapsed the other way.
  • Outside the ring or inside the hole: no solution.

Two practical notes. First, the hole exists only because the links have different lengths. If L1 = L2, the hole shrinks to the single point r = 0, and at that point there are infinitely many solutions (θ2 = 180° with any θ1), which no IK function can list. Unequal links, like 0.4 m and 0.3 m, make the inner boundary visible. Second, this ring is the ideal workspace. A real arm has joint limits, cables and its own body in the way, so it reaches only part of the ring.

04. Closed-form inverse kinematics

Inverse kinematics (IK) runs the other way: given a target (x, y), find θ1 and θ2. For this arm there is a closed-form answer in two steps.

Step 1: the elbow angle. Square both FK equations and add them. The cross terms combine into cos θ1 cos(θ1 + θ2) + sin θ1 sin(θ1 + θ2) = cos θ2, and the squared terms collapse because cos² + sin² = 1. θ1 drops out completely: 

x² + y² = L1² + L2² + 2·L1·L2·cos θ2

cos θ2 = (x² + y² − L1² − L2²) / (2·L1·L2)
sin θ2 = ±√(1 − cos² θ2)
θ2     = atan2(sin θ2, cos θ2)

This is the law of cosines for the shoulder-elbow-tool triangle from section 03. The ± sign is the choice between the two elbow positions. If the formula gives |cos θ2| > 1, the target is outside the ring and there is no solution.

Step 2: the shoulder angle. The direction from the shoulder to the target is atan2(y, x). That direction is θ1 plus the extra angle that link 2 adds, seen from the shoulder. That extra angle is just the FK of the arm with θ1 = 0: the tip would be at (L1 + L2 cos θ2, L2 sin θ2). Subtract it: 

θ1 = atan2(y, x) − atan2(L2·sin θ2, L1 + L2·cos θ2)

PythonRobotics uses the same pair of formulas: it computes θ2 with an arccosine of the law-of-cosines expression and then θ1 = atan2(y, x) − atan2(l2 sin θ2, l1 + l2 cos θ2).[1] The Modern Robotics course materials describe the 2R solution with the same two tools, the two-argument arctangent and the law of cosines.[2] Section 06 explains why this lesson uses atan2 for θ2 instead of an arccosine.

05. Worked example: two answers for one target

Take the target (x, y) = (0.5, 0.2) m. Its distance from the shoulder is r = √0.29 = 0.539 m, which is inside the ring, so expect two solutions. 

cos θ2 = (0.25 + 0.04 − 0.16 − 0.09) / (2·0.4·0.3) = 0.04 / 0.24 = 0.1667
sin θ2 = ±√(1 − 0.1667²) = ±0.9860
θ2     = ±80.406°

atan2(y, x)                          = atan2(0.2, 0.5)     = 21.801°
atan2(L2·sin θ2, L1 + L2·cos θ2) = atan2(±0.2958, 0.45) = ±33.319°

Solution A (θ2 ≥ 0): θ1 = 21.801° − 33.319° = −11.517°,  θ2 = +80.406°
Solution B (θ2 < 0): θ1 = 21.801° + 33.319° =  55.120°,  θ2 = −80.406°

Check by running FK on both. Solution A puts the elbow at (0.392, −0.080), below the line from the shoulder to the target. Solution B puts it at (0.229, 0.328), above that line. Both tips land on (0.500, 0.200). The labels A and B match the simulator, whose buttons are named “Solution A (θ2 ≥ 0)” and “Solution B (θ2 < 0)”.

For this target, Solution A is the “elbow down” posture and B is “elbow up”, the same naming as in lesson 1.6. Be careful with those names, though. The sign of θ2 only says which side of the shoulder-to-target line the elbow is on (positive θ2 puts it on the clockwise side). Whether that side looks “down” depends on where the target is. Mirror the target to (−0.5, 0.2): Solution A becomes (124.880°, +80.406°) with its elbow at (−0.229, 0.328), now above the line, so A is the elbow-up posture there. Judge “up” and “down” from the picture, not from the sign.

Which solution should a controller use? A common rule is to pick the branch closest to the current joint angles, within the joint limits. PythonRobotics uses a simpler rule: if θ1 comes out negative, it flips the sign of θ2 to take the other branch.[1] Whatever the rule, a controller should not switch branches in the middle of a straight-line move. To get from one elbow posture to the other, link 2 has to swing through the straight (θ2 = 0) or folded (θ2 = 180°) pose, which section 09 shows is a singularity. This is one reason industrial controllers store a configuration with each taught point (see ABB's robconf in lesson 2.3).

06. Why atan2, and not atan or acos

The ordinary arctangent, atan(y/x), only sees the ratio y/x. That ratio is the same for (0.5, 0.2) and (−0.5, −0.2), and the same for (−0.5, 0.2) and (0.5, −0.2), so atan cannot tell opposite quadrants apart. For the target (−0.5, 0.2), atan(y/x) returns −21.80°, while the true direction, atan2(0.2, −0.5), is 158.20°. The arm would point the wrong way. atan(y/x) also divides by zero for any target on the y-axis, such as (0, 0.7). atan2(y, x) takes both numbers separately, uses their signs to find the quadrant, and works for x = 0.

For θ2 it is tempting to write θ2 = acos(cos θ2), as PythonRobotics does.[1] That works, but it has two weaknesses:

  • It hides one branch. acos only returns angles between 0 and 180°, so it always gives Solution A. You must remember to add the negative branch yourself.
  • It is touchy at the edges. The slope of acos becomes infinite as its input approaches ±1, which is exactly the boundary of the ring. A tiny error in cos θ2 there becomes a large error in θ2. And an input even slightly outside [−1, 1] is an error, as the next section shows.

Writing θ2 = atan2(sin θ2, cos θ2) uses both pieces of information, gives either branch by the sign you choose for sin θ2, and is well behaved everywhere except at (0, 0).

07. Edge cases: rounding at the boundary

The formulas in section 04 are exact on paper. On a computer, every number carries a small rounding error, and the boundary of the ring is where those errors cause trouble. The following results come from running the code in this lesson in Python with ordinary double-precision floats, using L1 = 0.4 and L2 = 0.3.

Problem 1: cos θ2 slightly above 1. Compute the tip of the fully stretched arm at θ1 = 60°, θ2 = 0 with FK, then feed that point back into the cos θ2 formula. Mathematically the result is exactly 1. The computer gets 1.0000000000000004. Python's math.acos then raises ValueError: math domain error, and NumPy's np.arccos returns nan with only a warning. The folded pose is similar: at θ2 = 180°, the computed value was −1.0000000000000002 for every θ1 tried. A point you computed from a perfectly valid pose is rejected as unreachable.

Problem 2: two solutions where there should be one. Now type the target (0, 0.7), which is exactly on the outer circle. The computed cos θ2 is 0.99999999999999989, just below 1. No error this time, but √(1 − cos² θ2) turns that error of about 10−16 into sin θ2 ≈ 1.5 × 10−8. A naive “if sin θ2 == 0” test fails, and the code reports two solutions that differ by about 10−8 rad. The square root amplifies rounding near the boundary.

The fix: clamp and snap with a tolerance.

  • If |cos θ2| > 1 + tol, the target really is out of reach: return no solution.
  • Otherwise clamp cos θ2 into [−1, 1], so rounding noise can never reach acos or the square root as an invalid value.
  • If |cos θ2| > 1 − tol, treat the target as on a boundary circle: set sin θ2 = 0 and return one solution.

The code below uses tol = 10−9. Points within that tolerance of a boundary are snapped to the single boundary solution, which moves the tip by a tiny amount. In a round-trip test over 100,000 random joint pairs (FK, then IK, then FK again), the largest tip error with this snapping was 5 × 10−12 m, far below anything a real robot can resolve.

These edge cases are not only academic. The PythonRobotics demo only checks the outer boundary: if the target is farther than l1 + l2, it sets θ2 = 0 and points the arm straight at the target. It has no check for the inner hole, because its two links are equal (l1 = l2 = 1), and it catches ValueError as “Unreachable goal”.[1] Since np.arccos returns nan instead of raising ValueError, that handler would not catch an out-of-range value. The file is a good visual demo, but not robust IK to copy.

08. Robust IK in Python

Here is the full solver, written for this lesson and tested with the round-trip check above. It returns a list: two solutions inside the ring, one on a boundary circle and none outside. The first entry always has θ2 ≥ 0 (Solution A), and θ1 is wrapped into (−180°, 180°] like the simulator's slider. 

from math import atan2, sqrt, cos, sin, pi

def fk(t1, t2, L1, L2):
    """Planar 2R forward kinematics: joint angles (rad) -> tip (x, y)."""
    return (L1*cos(t1) + L2*cos(t1 + t2),
            L1*sin(t1) + L2*sin(t1 + t2))

def ik(x, y, L1, L2, tol=1e-9):
    """Closed-form IK. Returns a list of (t1, t2): 2 inside the annulus,
    1 on its boundary, 0 if unreachable. First entry has t2 >= 0."""
    c2 = (x*x + y*y - L1*L1 - L2*L2) / (2*L1*L2)    # law of cosines
    if abs(c2) > 1 + tol:
        return []                                    # outside annulus
    c2 = max(-1.0, min(1.0, c2))                     # clamp rounding noise
    if abs(c2) > 1 - tol:                            # on a boundary circle
        branches = [0.0]                             # sin(t2) = 0: one solution
    else:
        s = sqrt(1 - c2*c2)
        branches = [s, -s]                           # two elbow branches
    sols = []
    for s2 in branches:
        t2 = atan2(s2, c2)
        t1 = atan2(y, x) - atan2(L2*s2, L1 + L2*c2)
        sols.append(((t1 + pi) % (2*pi) - pi, t2))   # wrap t1 to (-pi, pi]
    return sols

if __name__ == "__main__":
    L1, L2 = 0.4, 0.3                                # the arm from lesson 1.6
    for target in [(0.5, 0.2), (0.0, 0.7), (0.1, 0.0), (0.6, 0.5)]:
        sols = ik(*target, L1, L2)
        print(target, len(sols), "solution(s)")
        for t1, t2 in sols:
            x, y = fk(t1, t2, L1, L2)
            print(f"  t1={t1*180/pi:8.3f} deg  t2={t2*180/pi:8.3f} deg"
                  f"  -> FK ({x:.6f}, {y:.6f})")

Output: 

(0.5, 0.2) 2 solution(s)
  t1= -11.517 deg  t2=  80.406 deg  -> FK (0.500000, 0.200000)
  t1=  55.120 deg  t2= -80.406 deg  -> FK (0.500000, 0.200000)
(0.0, 0.7) 1 solution(s)
  t1=  90.000 deg  t2=   0.000 deg  -> FK (0.000000, 0.700000)
(0.1, 0.0) 1 solution(s)
  t1=   0.000 deg  t2= 180.000 deg  -> FK (0.100000, 0.000000)
(0.6, 0.5) 0 solution(s)

The four targets cover every case from section 03. (0.5, 0.2) is inside the ring. (0, 0.7) is on the outer circle: the arm points straight up, fully stretched. (0.1, 0) is on the inner circle: link 1 points along x to (0.4, 0) and link 2 folds straight back to (0.1, 0). (0.6, 0.5) is 0.781 m away, beyond the 0.7 m reach, and its cos θ2 works out to 1.5.

09. The Jacobian and singularities

Kinematics so far was about positions. The Jacobian is about velocities. Differentiate the FK equations with respect to time and collect the joint speeds θ̇1 and θ̇2: 

[ ẋ ]   [ −L1·sin θ1 − L2·sin(θ1+θ2)   −L2·sin(θ1+θ2) ] [ θ̇1 ]
[ ẏ ] = [  L1·cos θ1 + L2·cos(θ1+θ2)    L2·cos(θ1+θ2) ] [ θ̇2 ]
             \_____________________________ J(θ) _____________________________/

Each column of J is the tool velocity produced by one joint turning at 1 rad/s. At the 1.6 example pose, θ1 = 30° and θ2 = 45°, J = [[−0.4898, −0.2898], [0.4241, 0.0776]]. Notice that the first column is (−y, x) of the tool: turning the shoulder swings the whole arm around the origin.

The determinant of J tells you whether the joints can move the tool in every direction. Multiply it out and use the identity sin(a − b) = sin a cos b − cos a sin b: 

det J = (−L1·s1 − L2·s12)(L2·c12) + (L2·s12)(L1·c1 + L2·c12)
      = L1·L2·(s12·c1 − c12·s1)
      = L1·L2·sin θ2            (s1 = sin θ1, s12 = sin(θ1+θ2), and so on)

For the 1.6 pose that is 0.12 · sin 45° = 0.0849 m², which matches a numerical determinant of the matrix above. Lecture notes on Jacobians reach the same formula and the same conclusions.[3] Three things follow from it:

  • The singular poses are θ2 = 0 and θ2 = 180°. det J = 0 exactly when the arm is fully stretched or fully folded.[3] θ1 does not appear, so the shoulder angle never matters.
  • The singular poses are the edges of the ring. Stretched means r = 0.7 m and folded means r = 0.1 m. The poses where IK has one solution instead of two (section 03) and the poses where J is singular are the same set.
  • The arm loses the radial direction. At θ1 = 0, θ2 = 0 the Jacobian is [[0, 0], [0.7, 0.3]]. Both columns point along y, sideways to the arm. Neither joint can move the tool along x, toward or away from the shoulder. The arm has dropped from two directions of motion to one.

Near a singularity the arm can still move radially, but only with very fast joints. To command a tool velocity you solve J·θ̇ = v for θ̇, which divides by det J. Take θ1 = 0 and ask for a radial tool speed of 0.1 m/s (outward along the line from shoulder to tool):

  • θ2 = 10°: the joints must turn at about 82°/s and −192°/s.
  • θ2 = 5°: about 164°/s and −383°/s.
  • θ2 = 1°: about 821°/s and −1,915°/s.

The joint speeds grow like 1/θ2. The condition number of J, a measure of how much it amplifies errors, grows the same way: about 4.4 at θ2 = 1 rad, 48 at 0.1 rad, 483 at 0.01 rad and 4,830 at 0.001 rad. This is the outer-workspace singularity from lesson 1.6, now with the formula behind it: a straight-line tool move near the edge of the ring asks for joint speeds that grow without limit.

10. From two links to a six-axis robot

An industrial arm uses the same ideas in 3D. Each joint adds a rotation and an offset, so forward kinematics becomes a product of 4 × 4 homogeneous transforms, one per joint, written either with Denavit–Hartenberg parameters (see 1.6) or as a product of exponentials. The Modern Robotics code library implements product-of-exponentials FK as FKinSpace(M, Slist, thetalist) and FKinBody, and computes the full 6 × n Jacobian with JacobianSpace and JacobianBody, the general version of the 2 × 2 matrix in section 09.[4][5]

Closed-form IK when the wrist is spherical. Most industrial arms have a spherical wrist: the last three joint axes meet at one point. Course slides and research papers trace closed-form solutions for this case to Pieper's 1968 work on arms with three consecutive axes intersecting at a point.[6] The wrist-centre position then depends only on joints 1 to 3, so IK splits into a position problem (find the wrist centre, with law-of-cosines geometry much like this lesson's elbow) and an orientation problem for joints 4 to 6. Each split brings its own two-way choices, such as elbow up or down and wrist flipped or not. Sources describe up to 8 solutions for this kind of arm; a reference page for the Puma 560 gives 8 “because of the different possible arm configurations”.[6][7] A general 6R arm with no special geometry is reported to have at most 16 solutions.[8] Treat these two counts as reported figures: they come from summaries of the sources, and a standard robotics textbook is the place to confirm them.

Numerical IK when there is no closed form. For a general arm, or a 7-axis arm, controllers solve IK numerically. The Modern Robotics library documents its function IKinBody as one that “Uses an iterative Newton-Raphson root-finding method”. It repeats θ ← θ + J+(θ)·error, where J+ is the pseudoinverse of the Jacobian, until the orientation and position errors are below set tolerances. It needs an initial guess of joint angles that is already close to the target pose, stops after a hard-coded 20 iterations, and reports success = False if it has not converged.[4][5] Peter Corke's Robotics Toolbox for Python offers a Levenberg–Marquardt solver, robot.ik_LM(Tep), and its README demonstrates it on the 7-axis Franka Panda, then checks the answer by running FK with robot.fkine(q). The README claims numerical IK can be solved “in as little as 4 microseconds”.[9]

The same update works on our 2-link arm and shows two weaknesses of numerical IK. Starting from θ = (0.1, 0.1) rad toward the target (0.5, 0.2), it converged to an error below 10−10 m in 7 iterations. It found only one answer, Solution B (55.12°, −80.41°), chosen by the starting guess; Solution A was never reported. Its raw angles, −304.88° and 639.59°, match that pose only after wrapping: plain Newton-Raphson ignores joint limits. It also divides by the Jacobian, so it struggles exactly where det J → 0, which is one reason practical solvers use damped methods such as Levenberg–Marquardt.

Try it
  1. Solve IK by hand for the target (0.5, 0.2) with L1 = 0.4 m and L2 = 0.3 m. You should get Solution A (−11.5°, +80.4°) and Solution B (55.1°, −80.4°). In the lesson 1.6 simulator, set θ1 = −12° and θ2 = 80°: the readout should show the tool near (0.504, 0.195), off slightly because the sliders move in whole degrees. Then press “Solution B (θ2 < 0)” and check that the arm jumps to about (54°, −80°) with the tool in the same place. The simulator solves from the rounded tool position, which is why it shows 54° rather than the exact 55.1°.
  2. Outer edge: solve the target (0, 0.7). You should get one solution, (90°, 0°). Set it on the sliders; the readout should report 0.700 m from the base and warn that the arm is fully stretched, a singularity.
  3. Inner edge: solve the target (0.1, 0), on the 0.1 m inner circle. You should get one solution, (0°, 180°). Set it on the sliders and look at the drawing: link 2 lies on top of link 1. The simulator only flags the stretched case, so decide for yourself, using det J = L1L2 sin θ2, whether this pose is also singular.
  4. Unreachable: compute cos θ2 for (0.6, 0.5) and for (0.05, 0.05). You should get 1.5 and about −1.02, both outside [−1, 1]. Tap near each point in the simulator and read its out-of-reach message.
  5. Run the Python code from section 08 with your own targets. Then write a naive version that computes t2 = acos(c2) with no tolerance checks, and give it the point fk(pi/3, 0.0, 0.4, 0.3). What happens, and which lines of the section 08 code prevent it? (Compare with section 07.)
