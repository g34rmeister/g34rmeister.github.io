8.1 From Wires to Networks

Gerald Lê

01. Discrete DC I/O: sinking and sourcing

In Lesson 1.7 The Industrial Robot Cell, we examined how a robotic manipulator functions within an automated work cell. In that lesson, we saw that a cell controller coordinates equipment using handshake signals, while safety signals are kept separate. In Lesson 2.5 End-of-Arm Tooling and I/O, we configured the digital inputs and digital outputs on the controller and tool flange that detect part presence and trigger pneumatic actuators. Before digital communication networks connected automated machines, every sensor and actuator communicated through dedicated electrical circuits. Understanding modern industrial networking begins with these direct current (DC) circuits that interface field devices to programmable logic controllers (PLCs).

In industrial automation, discrete input and output signals operate primarily on direct current. Sinking and sourcing terminology applies only to DC input and output circuits.[1] Alternating current (AC) circuits reverse polarity continuously, so sinking and sourcing concepts do not apply to them. Direct current circuits maintain fixed positive and negative polarities. Sinking or sourcing input and output points can conduct current in one direction only.[1] Because current flows in one direction through solid-state switches and optical isolators, understanding how current enters and exits each terminal is necessary when wiring devices to a PLC or robot controller.

The terms sinking and sourcing define how an electrical circuit provides a path relative to the power supply rails. Sinking provides a path to supply common (-).[1] Sourcing provides a path to supply source (+).[1] A sourcing circuit connects the positive supply rail to the load, driving conventional current out through the terminal. A sinking circuit connects the load down to the negative supply rail, pulling current into the terminal toward electrical common.

To reduce wiring complexity and physical module size, PLC I/O cards do not provide isolated pairs of positive and negative terminals for each individual point. Most PLC input or output points are grouped together to share a return path called a common.[1] For example, a card might have eight signal terminals and one common terminal for all eight. This arrangement saves space in electrical enclosures by minimizing the number of return conductors routed through wire ducts.

However, grouping return lines concentrates current across the shared conductor. In output circuits sharing a common return path, the current flowing through the common terminal can reach several amperes.[1] For example, when eight output actuators on a card energize simultaneously to power pneumatic solenoid valves, the individual return currents combine at the single common terminal before returning to the power supply. Panel builders must size common wiring conductors to handle this combined current without overheating or causing voltage drops across the return rail.

02. Three-wire sensors: NPN and PNP field devices

Discrete sensors on automated machinery include inductive proximity switches, photoelectric sensors, and capacitive level detectors. While mechanical limit switches use two conductors to open or close a contact, electronic sensors require a three-wire interface. A three-wire field device has connections for a supply source (+), a supply common (-), and an output signal.[2] The supply source wire connects to positive DC potential, and the supply common wire connects to DC negative common. These two conductors supply continuous operating power to the internal sensing circuitry. The third conductor carries the switched digital output signal to the controller.

The internal transistor configuration determines how the sensor switches this signal line. Sinking field devices use NPN transistor outputs and sourcing field devices use PNP outputs.[2] An NPN sensor contains an internal transistor that switches the output signal line down to supply common (-). When the sensor detects a target, it sinks current from the signal line to common. A PNP sensor contains an internal transistor that switches the output signal line up to supply source (+). When active, it sources current from the positive supply rail out into the signal line.

For electrical current to flow, a closed circuit must exist between the positive supply rail and the negative common rail. An NPN sinking field device requires a PLC I/O module with a sourcing input.[2] When an NPN sensor turns on, it opens a path to negative common, so the PLC sourcing input must supply positive current through its optical isolator into the sensor. Conversely, a PNP sourcing sensor outputs positive current, requiring a sinking PLC input that conducts the incoming current down to common.

Many PLC input modules allow the shared common terminal to connect to either positive or negative voltage, accommodating either sensor type. However, internal grouping imposes a strict constraint. All I/O points sharing a common terminal on a sink/source module must be wired as only sinking or only sourcing.[2] If an engineer connects a group's common terminal to positive supply potential to support NPN sinking sensors, every point in that group must be an NPN sensor. Mixing NPN and PNP sensors on the same shared common terminal prevents current from circulating through the opposing circuits.

03. Point-to-point wiring and fieldbus technology

In early automated facilities, point-to-point wiring was the standard method for connecting machinery to control enclosures. Every proximity sensor, push button, valve solenoid, and interlock switch required dedicated copper conductors routed directly back to input and output terminals in the PLC cabinet. In complex manufacturing cells, this created thick wiring bundles containing hundreds of individual conductors. Installing these bundles through conduit and routing them through robot dress packs required substantial labor. Furthermore, diagnosing broken wires under repetitive mechanical flexing was difficult.

To solve the physical limitations of point-to-point wiring, automation manufacturers developed digital networking architectures. Fieldbus technology served as a replacement for point-to-point wiring when connecting sensors and field devices to PLCs.[3] Rather than running individual wires from every device back to the main cabinet, fieldbus networks connect multiple field devices using a single shared digital cable. Remote I/O blocks mounted directly on the machine gather local sensor signals, digitize them, and transmit them to the central controller across this shared communication bus.

The first fieldbuses used simple serial links. Serial fieldbus networks originally dominated because early Ethernet was expensive and non-deterministic.[3] Non-deterministic means the network cannot guarantee how long a message takes to arrive.

In industrial automation, unpredictable delivery times cannot be tolerated. If a robot arm moves at high speed, input signals from limit switches or interlocks must arrive within a guaranteed time window. Several of those early serial protocols became the DeviceNet, PROFIBUS DP and CANopen protocols still used today.[3]

04. The shift to industrial Ethernet

As manufacturing automation expanded, the data requirements of production equipment outgrew serial fieldbus bandwidth. Industrial versions of standard Ethernet hardware, such as managed and unmanaged switches, helped by improving speed and determinism and reducing data collisions.[3]

Industrial Ethernet allows multiple distinct protocols to operate simultaneously across the same physical cable.[3]

This multi-protocol capability allows a single industrial network cable to serve multiple plant functions. For example, a single Ethernet cable connected to a robot controller can carry real-time cyclic control data to the PLC, deliver supervisory production statistics through OPC UA, and transmit configuration commands from an engineering workstation. By running multiple protocols over standard cabling, manufacturing plants simplified their network architecture and linked machine controllers directly to plant information systems.

05. Cyclic and acyclic communication

To support both real-time machine control and background data collection, industrial communication protocols divide data transmission into two distinct modes: cyclic data exchange and acyclic data exchange. This division ensures that administrative tasks do not delay time-sensitive machine operations.

In manufacturing automation, controllers require regular, predictable updates to coordinate moving machinery. Inputs and outputs are transferred between a controller and I/O devices cyclically at a defined update cycle time.[4] At each update interval, the controller transmits output commands to actuators and reads input states from field sensors.

In contrast, other types of operational information are exchanged only occasionally. Acyclic communication transmits diagnostic data on an as-needed basis rather than adhering to a fixed cyclic update schedule.[4] For example, uploading an error log from a motor drive, modifying a controller parameter, or reading temperature trends occurs only when requested by an operator or triggered by a fault event. These requests are answered when they arrive instead of on a fixed schedule.

06. Network topologies and Device Level Ring resilience

The arrangement of physical cables and network nodes in an industrial facility forms the network topology. Industrial networks support multiple physical topologies including line, ring, and star configurations.[4] Each topology offers specific characteristics for installation and fault tolerance:

  • Star topology: Every node connects via an individual cable directly to a central switch. If one cable is damaged, only that single node loses communication. However, star topologies require extensive cabling runs converging on central enclosures.
  • Line topology: Nodes connect sequentially from one device to the next using two-port embedded switches. This daisy-chain approach minimizes cable lengths and eliminates external switches. However, if any cable is broken or a device powers off, communication to all downstream nodes is lost.
  • Ring topology: The last device in a line topology connects back to the start, closing the loop. This configuration provides a redundant physical path while keeping cabling runs shorter than a star configuration.

In standard Ethernet, looping cables creates broadcast storms as broadcast packets circulate endlessly, disabling the network. To utilize ring topologies safely, industrial protocols implement media redundancy management. Device Level Ring (DLR) is an EtherNet/IP protocol defined by ODVA.[5] In a DLR network, one device is configured as the active ring supervisor, while the remaining devices act as ring nodes. The active ring supervisor transmits beacon frames through both of its ring ports to monitor network health.[5]

During normal operation, one of the supervisor's ring ports is blocked, so the ring behaves like a line with no loop.[5] It continuously sends beacon frames out of both ports to confirm ring continuity. If a cable breaks or a node loses power, beacon frames cease arriving at the opposite supervisor port. The supervisor then unblocks its blocked port so traffic can reach every node through the remaining path.

Fast network recovery is necessary to prevent automated processes from stopping when a cable is damaged. A copper Device Level Ring network achieves a worst-case recovery time of 2890 µs using default beacon settings.[5]

To maintain this recovery speed, network size must be controlled. Rockwell Automation recommends limiting a Device Level Ring network to 50 or fewer nodes to avoid degraded recovery time and network performance.[5] Too many ring nodes make multiple faults more likely and slow down fault detection and recovery, so larger installations are split into separate rings.[5]
