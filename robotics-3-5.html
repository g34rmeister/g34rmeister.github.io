3.5 ROS Tools

Gerald Lê

01. RViz

RViz is ROS’s 3D visualization tool. It shows what the robot “sees” and “thinks”: its 3D model, camera images, laser scans, point clouds, maps, planned paths and coordinate frames. RViz does not simulate anything; it displays data that is already flowing through ROS, which makes it the first tool to open when debugging. In ROS 2 it starts with ros2 run rviz2 rviz2.

02. rqt and rqt_graph

rqt is a graphical framework that runs ROS tools as plugins in one dockable window. Start it with rqt and pick plugins from the Plugins menu. One of the most useful is rqt_graph, which draws the running nodes and the topics connecting them, so you can see at a glance who publishes to whom: 

ros2 run rqt_graph rqt_graph

03. Gazebo

Gazebo is a 3D robot simulator with physics. It simulates the robot, its sensors and its surroundings, so you can test code on a virtual robot before running it on real hardware. Gazebo connects to ROS 2 through the ros_gz bridge packages, so the same nodes can drive either the simulated robot or the real one: 

sudo apt install ros-lyrical-ros-gz

Each ROS 2 release is paired with a Gazebo release: Lyrical with Gazebo Jetty, and Jazzy with Gazebo Harmonic. The older simulator, Gazebo Classic, reached end of life on January 31, 2025, so new projects should use the current Gazebo.

04. ros2 bag

ros2 bag records the messages on chosen topics to a file so you can inspect, share and replay them later. That lets you test code against the same sensor data again and again without the robot running. With Turtlesim running, for example: 

ros2 bag record -o subset --topics /turtle1/cmd_vel /turtle1/pose
ros2 bag info subset
ros2 bag play subset

Press Ctrl + C to stop recording. Playing the bag back republishes the recorded velocity commands, and the turtle repeats the same path.

05. ROS packages

Most ROS functionality comes from packages. Some of the most widely used:

  • Nav2: the ROS 2 navigation stack: localization, path planning and obstacle avoidance for mobile robots.
  • MoveIt 2: motion planning for robot arms, including inverse kinematics and collision checking.
  • ros2_control: a framework for connecting controllers to robot hardware.
  • tf2: keeps track of coordinate frames (where the camera is relative to the gripper, for example) over time.
  • robot_state_publisher: publishes the positions of a robot’s parts from its model and joint states.
  • slam_toolbox: builds maps with SLAM while a robot explores.
Try it
  1. While driving the turtle, open rqt_graph and check that it matches the diagram above.
  2. Record a bag while you draw a shape, reset the simulator with ros2 service call /reset std_srvs/srv/Empty, and play the bag back to repeat the drawing.
