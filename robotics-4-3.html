      4.3 Installing ROS on Your Local Environment

      Gerald Lê
      Chapter 4, lesson 3 of 10 ← Previous: 4.2 ROS 1 vs. ROS 2 Next: 4.4 Running Your First Example (Turtlesim) →

      01. Picking the right install method for your computer

      Installing Robot Operating System 2 (ROS 2) is not like wiping your laptop to replace Windows or macOS. ROS 2 runs on top of your existing operating system as a set of tools and libraries. Picking the right install method up front saves you hours of broken commands. That is true whether you use an Ubuntu laptop, a Windows personal computer (PC), or a Mac.

      Each ROS 2 release targets a specific Long-Term Support (LTS) version of Ubuntu Linux. On other operating systems, you may need to build ROS 2 from source code or run it inside a container.[1]

      New learners often hit install errors because they do not know which systems a release officially supports. Ready-to-install binary packages only exist for top-tier platforms. On anything else, you have to compile from source or use a container.[2]

      This lesson walks you through installing our target release: ROS 2 Lyrical Luth. It came out on May 22, 2026 and has support until May 2031.[3][4] You will learn how platform support works, what commands to run, how to load ROS 2 in your terminal, and how to fix common setup mistakes.

      02. Which computers ROS 2 supports best

      Before you download anything, check how well ROS 2 supports your computer. Not every operating system gets an easy installer, and some setups take extra work. Knowing where your Ubuntu laptop, Windows PC, or Mac stands tells you what to expect.

      In ROS 2, a "platform" means three things together: an operating system, a central processing unit (CPU) architecture, and a networking middleware. Each release publishes a supported-platforms document that groups platforms into three support tiers:[5][6]

      • Tier 1: The ROS 2 team runs unit tests and other checks on these platforms frequently. That includes continuous integration (CI) builds, nightly runs, packaging checks, and speed tests. Bugs on Tier 1 platforms get top priority and can delay a release.[5] For ROS 2 Lyrical Luth, Tier 1 platforms are Ubuntu 26.04 LTS (on amd64 Intel/AMD chips and arm64 Arm chips) and Windows 11 (on amd64). Ubuntu gets Debian packages and binary archives, while Windows 11 gets a binary archive.[6]
      • Tier 2: These platforms get periodic CI builds and tests with public results. Known errors are fixed on a best-effort basis, meaning as time allows.[5] For Lyrical, Red Hat Enterprise Linux 10 (RHEL 10) on amd64 is Tier 2. It offers Red Hat Package Manager (RPM) packages and a binary archive.[6][2]
      • Tier 3: The development team runs no tests on these platforms. They appear on the list only because community reports say the release works.[5] For Lyrical, macOS, Ubuntu 24.04, Debian Trixie, and others are Tier 3. Using Lyrical on any Tier 3 platform means building it from source.[6]
      For the curious: how ROS 2 used to track platforms (REP 2000)

      Up to the Kilted Kaiju release, ROS 2 listed the target platforms for every release in a document called ROS Enhancement Proposal 2000 (REP 2000). Starting with Lyrical Luth, REP 2000 no longer covers new releases. Instead, the platform list lives in each release’s own documentation.[7][6]

      03. How a native Ubuntu install works

      If your computer runs Ubuntu Linux, you have the easiest path in this course. Installing ROS 2 on Ubuntu works much like installing other software through Ubuntu’s built-in package tool. Before you run any commands, look at the four stages so you know what each step does.

      Ubuntu Linux is the main home of ROS. Installing Debian (.deb) packages is the recommended route. They pull in needed libraries automatically and update alongside your regular system updates.[2] Installing ROS 2 Lyrical Luth on Ubuntu 26.04 LTS follows four stages: set up your system (text encoding and software sources), install ROS, set up your environment, and test the install.[8]

      04. Preparing Ubuntu and adding the ROS software source

      Ubuntu does not include ROS 2 in its default app catalog out of the box. Before you install ROS 2 on your Ubuntu laptop, you do two quick prep steps. First, you make sure your terminal handles standard text characters. Second, you tell Ubuntu’s package tool where to download ROS 2 safely.

      Step 1: Verify UTF-8 Locale. A locale controls how your system formats text and characters. Make sure your system uses a locale that supports Unicode Transformation Format 8-bit (UTF-8).[8] Minimal environments, such as Docker containers, may start with a bare-bones locale like Portable Operating System Interface (POSIX). The ROS developers test with the en_US.UTF-8 settings below, though any UTF-8 locale should work.[8]

      Check and generate a UTF-8 locale using the official commands:[8] 

      locale  # check for UTF-8
sudo apt update && sudo apt install locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
locale  # verify settings

      Step 2: Enable Universe and add the ROS 2 apt source. Ubuntu groups extra community packages in a catalog called Universe. First make sure the Ubuntu Universe repository is turned on using Ubuntu’s Advanced Package Tool (apt):[8] 

      sudo apt install software-properties-common
sudo add-apt-repository universe

      Next, install the ros2-apt-source package. It provides both the digital signing keys and the apt source setup for the ROS repositories. apt uses those keys to check that downloaded packages really come from the ROS project. Because it is installed as a package, your source setup also updates automatically when new versions come out.[8] 

      sudo apt update && sudo apt install curl -y
export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb

      Those commands install curl to download files, fetch the latest release tag from GitHub, download the matching .deb file, and install it with dpkg. Optionally, you can also install the developer tools you will need when you build your own packages:[8] 

      sudo apt update && sudo apt install ros-dev-tools

      05. Choosing Desktop or Base and installing ROS 2

      Now that Ubuntu knows where to find ROS 2, you are ready to install it. You choose between two main bundles depending on whether your computer has a screen. A laptop or lab workstation needs the visual tools, while a small computer riding inside a robot only needs the core software.

      Once the repository is ready, refresh your package cache and update your system. You do this because ROS packages are built on frequently updated Ubuntu systems:[8] 

      sudo apt update
sudo apt upgrade

      ROS 2 offers two main install choices:[8]

      • Desktop Install (Recommended): Includes ROS, the RViz visualization tool, demos, and tutorials. The desktop package extends ros_base with high-level packages like visual tools and demos.[8] For a workstation or laptop, install Desktop: 
        sudo apt install ros-lyrical-desktop
      • ROS-Base Install (Bare Bones): Includes communication libraries, message packages, and command-line tools, with no graphical user interface (GUI) tools.[8] This fits a computer without a screen, such as a single-board computer mounted inside a mobile robot: 
        sudo apt install ros-lyrical-ros-base

      ROS 2 programs talk to each other through a networking layer called Data Distribution Service (DDS). The default middleware is Fast DDS. You can install other ROS Middleware (RMW) options as extra packages if your project needs them.[8]

      06. Loading ROS 2 into your terminal

      Right after installing ROS 2, typing ros2 in a fresh terminal usually fails with bash: ros2: command not found. That happens because Ubuntu keeps ROS 2 in its own folder instead of mixing it into your main system folders. You fix it by running a setup script that tells your terminal where ROS 2 lives.

      Until you run ("source") the setup files, your shell cannot find ROS commands or ROS packages.[9] The Debian packages place ROS 2 under /opt/ros/lyrical/. Running source /opt/ros/lyrical/setup.bash lets your current terminal session find the ros2 command and its libraries.[9][8] If you use a different shell, replace .bash with .sh or .zsh.[8]

      Sourcing setup.bash runs setup scripts ("environment hooks") that add the ROS install folder to the front of several shell variables:[10]

      • PATH: Adds /opt/ros/lyrical/bin to the front, so your shell finds the ros2 command-line tool.[10]
      • LD_LIBRARY_PATH: Adds /opt/ros/lyrical/lib to the front, so compiled C++ programs find ROS shared libraries at run time on Linux.[10]
      • PYTHONPATH: Adds the ROS 2 Python package folder, so Python scripts can import rclpy and message definitions.[10]
      • AMENT_PREFIX_PATH: Adds the install prefix, which ROS tools use to locate installed packages.[10]

      Sourcing also sets variables such as ROS_DISTRO and ROS_VERSION.[9] Remember that sourcing only affects the terminal window you run it in. If you append the line below to your shell startup script (~/.bashrc), every new terminal loads ROS 2 automatically:[9] 

      echo "source /opt/ros/lyrical/setup.bash" >> ~/.bashrc

      07. Installing ROS 2 on a Windows PC

      If your computer runs Windows, you do not need to erase your hard drive or dual-boot Linux to learn ROS 2. You have two main options: run a real Ubuntu terminal inside Windows, or install a native Windows build of ROS 2. Most beginners get a smoother start with the built-in Ubuntu option because most ROS guides assume Linux.

      Option A: Windows Subsystem for Linux (WSL 2). WSL runs a real Ubuntu system inside Windows. Even the ROS guide for the Webots simulator notes that WSL improves the ROS 2 experience because it runs on Linux rather than native Windows.[11] On Windows 11 (or Windows 10 build 19044 and later), WSL 2 can also open Linux GUI apps like RViz2 and Turtlesim as regular desktop windows. They use hardware-accelerated Open Graphics Library (OpenGL) graphics once you install the matching graphics processing unit (GPU) driver.[12]

      To set up WSL 2 with Ubuntu 26.04, open Windows PowerShell and run the command below. You can run wsl --list --online first to see the available names.[13] 

      wsl --install Ubuntu-26.04

      Once Ubuntu finishes installing, open the Ubuntu terminal and follow the native Ubuntu steps in sections 03 through 06.[11] If RViz crashes under WSL 2, forcing software rendering with export LIBGL_ALWAYS_SOFTWARE=true is a documented workaround.[14]

      Option B: Native Windows 11 binary archive. If you need tight integration with Windows apps or Visual Studio C++ tools, ROS 2 offers a pre-built Windows archive. Only Windows 11 is supported.[15] It includes all ros_base packages, though only some desktop packages. Dependencies come from conda-forge and are managed with pixi, a tool built on conda-forge that handles binary dependencies on Windows. Compiling C++ packages also requires Visual Studio Build Tools 2022.[15]

      To set it up, create a short folder such as C:\dev, install pixi, and download the Windows archive from the ROS 2 GitHub releases page. Then unpack it, install dependencies, and source the environment in every new Command Prompt.[15] Watch the filename: the docs show windows-release-amd64.zip, while the releases page uses names like ros2-lyrical-2026-08-07-windows-AMD64.zip. Look for a name ending in -windows-AMD64.zip:[16] 

      cd C:\dev\lyrical
pixi install
pixi run python preinstall_setup_windows.py
pixi shell
call C:\dev\lyrical\local_setup.bat

      Those five lines enter your folder, install dependencies with pixi, run the Windows pre-install script, open a pixi shell, and load ROS 2 in that Command Prompt.

      08. Installing on a Snapdragon Windows laptop (Arm64)

      Some newer Windows laptops, such as those with Qualcomm Snapdragon processors, use an Arm64 chip instead of an Intel or AMD (x64) chip. That chip difference changes how you install ROS 2, because the native Windows ROS 2 archive is built for Intel and AMD chips only. You can still run native Tier 1 ROS 2 on a Snapdragon laptop by running Ubuntu inside WSL 2.

      To check which chip your laptop uses, open Settings, then System, then About, and look at the “System type” line. The Lyrical platform table lists Windows 11 on amd64 as Tier 1 and has no Windows arm64 entry at all.[6] The Lyrical release downloads include a Windows AMD64 archive and an Ubuntu aarch64 archive, with nothing for Windows on Arm.[16]

      What does not work. There is no official native ROS 2 build for Windows on Arm, so Option B from section 07 is not available.[6] Windows 11 on Arm can run many x64 apps through an emulator called Prism.[17] However, we found no report testing the x64 ROS 2 archive under emulation. It is unsupported, so we do not recommend it. Emulation also does not cover hardware drivers, which must be native Arm64.[18] Two industrial simulators, Universal Robots’ e-series Universal Robots Simulator (URSim) and ABB RobotStudio, also lack tested Arm support (see the details box below).

      Recommended path: WSL 2 with Ubuntu 26.04 arm64. WSL supports both x64 and Arm64 CPUs,[19] and the Ubuntu 26.04 entry used by wsl --install includes a separate arm64 image.[20] The same command from section 07 gives you native arm64 Ubuntu on a Snapdragon laptop: 

      wsl --install Ubuntu-26.04
# then, inside Ubuntu:
dpkg --print-architecture   # should print arm64

      Ubuntu 26.04 on arm64 is a Tier 1 platform for Lyrical,[6] and the ROS buildfarm builds Lyrical packages for Ubuntu 26.04 on arm64.[21] You can follow sections 03 through 06 without changes, install ros-lyrical-desktop with apt, and run the test in section 10. Keep the default Fast DDS middleware, because RTI Connext DDS is not supported on arm64 for Lyrical.[6] If your course uses Jazzy instead, install Ubuntu 24.04 in WSL, since Jazzy’s arm64 packages are built for that Ubuntu release.[7]

      Graphics expectations. Windows Subsystem for Linux GUI (WSLg) still opens RViz2 and Turtlesim windows, though you may not get GPU acceleration. Microsoft’s guide lists virtual GPU (vGPU) drivers for Intel, AMD, and NVIDIA only.[12] An open bug report from June 2026 notes that WSL 2 on Snapdragon laptops cannot reach the Qualcomm GPU. Graphics then fall back to software rendering on the CPU.[22] Check that issue for updates, because a fix may arrive later. If RViz crashes, use the LIBGL_ALWAYS_SOFTWARE=true workaround from section 07.[14] Turtlesim and simple RViz scenes should still work on the CPU. Gazebo will be slow, and the Gazebo project treats arm chips as best-effort rather than officially supported.[23]

      Where to run heavy tools. Run heavy Gazebo simulations and URSim on an x64 lab PC or a cloud virtual machine (VM) running Ubuntu 26.04, which also gets Tier 1 packages. RobotStudio is Windows software, so run it on an x64 Windows PC.[6] ROS on your laptop can still talk to that machine over the network if both use the same ROS_DOMAIN_ID and the firewall allows DDS traffic (see section 12).[9][14] For command-line work, you can also run Docker inside WSL, because the official ros:lyrical images ship for both amd64 and arm64.[24] If you use an Apple silicon Mac, skip Windows VMs and install Ubuntu 26.04 arm64 directly as shown in section 09.

      Setup on a Windows on Arm laptop Lyrical status Verdict
      WSL 2 with Ubuntu 26.04 arm64 and ros-lyrical-desktop Tier 1 packages; RViz may use CPU rendering Recommended
      Native ROS 2 for Windows on Arm No official build Not available
      x64 Windows archive under Prism emulation Untested and unsupported Avoid
      ros:lyrical Docker image inside WSL Official arm64 image Good for command-line work
      Heavy Gazebo, URSim, RobotStudio Slow or not supported on Arm Use an x64 lab PC or cloud VM
      For the curious: older releases, vendor simulator reports, and Mac Windows VMs

      Earlier ROS 2 releases such as Jazzy followed the same Windows rule. ROS Enhancement Proposal 2000 (REP 2000), the older platform list, listed Windows on amd64 only.[7]

      Universal Robots distributes its e-series URSim simulator as a Docker image.[25] Users who ran it under amd64 emulation on Arm-based Macs reported that it starts but displays “No Controller”.[26] ABB RobotStudio is a Windows desktop application, and we could not find an official statement that it supports Windows on Arm. In a 2013 community thread about running it in a VM on a Mac, a reply called that an unsupported hardware configuration.[27]

      Running Windows 11 on Arm in a VM on an Apple silicon Mac brings all of the limits above. In addition, WSL 2 is reportedly unavailable inside that VM because it needs nested virtualization.[28]

      09. Running ROS 2 on a Mac

      If you use a Mac, installing ROS 2 directly on macOS takes a long source build and often hits snag points. Instead of fighting macOS directly, Mac users get a much smoother experience by running Ubuntu Linux inside a virtual machine or a Docker container. Both workflows let you follow the regular Ubuntu steps without compiling ROS 2 from scratch.

      For Lyrical Luth, macOS is a Tier 3 platform. There are no official binary packages, so running Lyrical directly on macOS means building it from source.[6] The official docs also note that ROS on macOS is community-supported and not recommended for new users.[1]

      On a Mac, especially one with Apple silicon, two workflows avoid a source build:

      • Virtual machine: Install the arm64 edition of Ubuntu 26.04 LTS in a VM app such as UTM or Parallels. Ubuntu 26.04 on arm64 is a Tier 1 platform with Debian packages, so inside the VM you can install ros-lyrical-desktop with apt as usual.[6]
      • Docker Containers: Containers are the documented route for platforms without binaries.[2][29] A container runs an isolated Linux setup on your Mac. The official ros:lyrical images (ros-core, ros-base, and perception) ship for both amd64 and arm64, so they run natively on Apple silicon.[24] We have not confirmed whether larger desktop images such as osrf/ros:lyrical-desktop ship for arm64. If they are amd64 only, they would need emulation on Apple silicon. A safer start is the base image, adding the desktop packages inside the container: 
        docker run -it ros:lyrical
# inside the container:
apt-get update && apt-get install -y ros-lyrical-desktop
        If you mainly need GUI tools, the Ubuntu 26.04 arm64 VM above is usually simpler. Showing graphical windows (RViz2 or Turtlesim) from a container on macOS needs extra display setup, such as an X Window System (X11) server, Virtual Network Computing (VNC), or a browser-based desktop inside the container.

      10. Testing your install with talker and listener

      Once installation and sourcing are done, test your setup right away with two small demo programs. One program (talker) sends out a greeting every second, and the other (listener) prints every greeting it hears. If the two terminals talk to each other, both your C++ and Python ROS tools are ready.

      Check that both the C++ and Python client libraries work. If you installed ros-lyrical-desktop, open two separate terminal windows.[8]

      In Terminal 1, source ROS 2 and start the pre-compiled C++ demo publisher node (talker):[8] 

      source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_cpp talker

      The talker publishes a “Hello World” string with a counter on the chatter topic once per second:[30] 

      [INFO] [1716400000.123456789] [talker]: Publishing: 'Hello World: 1'
[INFO] [1716400001.123456789] [talker]: Publishing: 'Hello World: 2'

      In Terminal 2, source ROS 2 and start the Python demo subscriber node (listener):[8] 

      source /opt/ros/lyrical/setup.bash
ros2 run demo_nodes_py listener

      The listener finds the talker automatically and prints each message it hears:[31] 

      [INFO] [1716400002.123456789] [listener]: I heard: [Hello World: 2]
[INFO] [1716400003.123456789] [listener]: I heard: [Hello World: 3]

      If the talker says it is publishing and the listener says it hears those messages, both the C++ and Python application programming interfaces (APIs) are working.[8] Press Ctrl+C in both terminals to stop.

      11. Installing two tools for building your own packages

      Right now you can run built-in demos, and in the next lesson you will start building your own ROS 2 packages. Custom code needs two helper tools that do not come in the basic desktop install. One tool builds your workspace, and the other installs any outside libraries your project needs.

      Before you create custom packages in lesson 4.4, install these two developer tools:[32][33]

      1. colcon (collective construction). colcon is the build tool for ROS 2 workspaces. It builds multi-package workspaces that mix build types such as ament_cmake, ament_python, and plain cmake. It also builds packages in parallel by default.[32] Install it with:[32] 

      sudo apt install python3-colcon-common-extensions

      2. rosdep (dependency resolver). Packages list their dependencies inside package.xml, including non-ROS “system dependencies” on outside libraries. Installing every missing library by hand is tedious and error-prone.[33]

      rosdep reads the dependency keys in the package.xml files of your workspace. It looks them up in the central rosdistro index and installs matching packages through your system package manager (apt on Ubuntu). It currently works on Linux and macOS, though not on Windows.[33] Install and initialize it once on your system:[33] 

      sudo apt install python3-rosdep
sudo rosdep init
rosdep update
      For the curious: older ROS build tools replaced by colcon

      colcon is an iteration on earlier ROS build tools: catkin_make, catkin_make_isolated, catkin_tools, and ament_tools.[32]

      12. Fixing common setup problems

      Even when you follow every step carefully, a missed terminal command or a firewall rule can keep talker and listener from connecting. Almost every early install problem comes from one of three causes: an unsourced terminal, mismatched domain numbers, or blocked network broadcasts. Check these three items before trying a reinstall.

      If your talker and listener test fails or commands behave unexpectedly, run through this checklist:[14]

      • Command Not Found: List your ROS environment variables by running printenv | grep -i ROS. If ROS_DISTRO=lyrical and ROS_VERSION=2 do not appear, you have not sourced setup.bash in that terminal window.[9]
      • Listener Hears Nothing (Domain ID Mismatch): Nodes only talk to nodes in the same domain, and the default domain is 0.[9][14] If one terminal ran export ROS_DOMAIN_ID=5 and the other did not, they cannot see each other. Run echo $ROS_DOMAIN_ID in both terminals to make sure they match.
      • Multicast Disabled or Blocked by a Firewall: DDS needs a network interface with multicast enabled, which is not always on by default.[14] Test multicast with the ROS 2 tool:[14] 
        # In Terminal 1:
ros2 multicast receive
# In Terminal 2:
ros2 multicast send
        If no “Hello World!” message arrives, your firewall may be blocking multicast. With Ubuntu’s Uncomplicated Firewall (ufw), allow User Datagram Protocol (UDP) multicast traffic (224.0.0.0/4) with:[14] 
        sudo ufw allow in proto udp to 224.0.0.0/4
sudo ufw allow in proto udp from 224.0.0.0/4
      Try it
      1. Open a fresh terminal, run printenv | grep -i ROS, and note what environment variables are present. If ROS 2 is sourced correctly, you should see ROS_DISTRO, ROS_VERSION, and AMENT_PREFIX_PATH.
      2. Open two terminals with matching ROS_DOMAIN_ID=42 and run the talker and listener. Verify that they discover each other. Then change the listener to ROS_DOMAIN_ID=43 and observe what happens.
      3. Run ros2 multicast receive in one terminal and ros2 multicast send in another to confirm that your local network and firewall permit DDS discovery broadcasts.
