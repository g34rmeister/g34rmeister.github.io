7.3 Image Processing Basics

Gerald Lê

01. Color spaces and grayscale conversion

In industrial robotics, vision systems capture camera frames to recognize workpieces, verify assembly, and guide end-effector motion. In 2.8 Vision-Guided Picking, we explored how robots use camera images to calculate coordinate offsets for picking unfixed parts. Before any coordinate shift or pose calculation can occur, the raw image stream must be processed to reveal recognizable geometric features.

Image processing pipelines begin by converting raw frames into suitable color representations. OpenCV converts color images using cv.cvtColor with flags such as cv.COLOR_BGR2GRAY for grayscale and cv.COLOR_BGR2HSV for hue-saturation-value representation.[1] Grayscale keeps one brightness value per pixel, which is all most edge and threshold steps need.

When parts must be differentiated by color rather than intensity alone, the HSV representation becomes valuable. In OpenCV HSV color space, the hue channel spans from 0 to 179 while saturation and value span from 0 to 255.[1]

Color segmentation isolates targets based on specific chromatic ranges. The function cv.inRange performs color segmentation by checking whether image array elements fall between lower and upper boundary arrays.[1] The result is a binary mask: white where the pixel is in range, black elsewhere. In the code below, a hue range of 100 to 140 on OpenCV's 0 to 179 scale picks out blue parts. 

import cv2 as cv
import numpy as np

# Load raw camera image and convert to grayscale and HSV
img_bgr = cv.imread('workpiece.jpg')
gray = cv.cvtColor(img_bgr, cv.COLOR_BGR2GRAY)
hsv = cv.cvtColor(img_bgr, cv.COLOR_BGR2HSV)

# Segment colored parts within defined HSV bounds
lower_bound = np.array([100, 150, 50])
upper_bound = np.array([140, 255, 255])
color_mask = cv.inRange(hsv, lower_bound, upper_bound)

02. Grayscale histograms, contrast, and equalization

Once an image is converted to a single-channel grayscale array, engineers analyze its intensity distribution. An image histogram collects data counts of image features organized into a set of predefined bins.[2] For example, an 8-bit single-channel image can be analyzed using 256 predefined bins to count how many pixels exhibit each brightness level.

The quality of feature extraction depends directly on image contrast. Contrast is defined as how well black can be distinguished from white at a given resolution, quantified by the difference between maximum and minimum intensities divided by their sum.[3] When the brightest and darkest values are close together, part edges blend into the background.

When an image's brightness values are bunched into a narrow range, histogram equalization spreads them out. OpenCV provides the equalizeHist function to normalize brightness and enhance contrast on 8-bit single-channel grayscale images.[4]

Illumination directly dictates the quality of the raw histogram before software equalization is even applied. Non-uniform lighting harms signal-to-noise ratios and makes image thresholding tasks more difficult.[5] Software cannot fully undo shadows and hot spots, which is why 7.2 treats lighting as the first fix.

03. Image thresholding: binary, adaptive, and Otsu

Binarization is the foundation of many industrial vision tasks. Converting an 8-bit grayscale image into a 1-bit binary image separates foreground workpieces from the background fixture or conveyor. In simple thresholding with cv.threshold and cv.THRESH_BINARY, pixels smaller than or equal to the threshold are set to 0 while all others are set to a maximum value.[6]

The threshold simulator needs JavaScript. With it on, you can adjust the threshold slider to see binary segmentation of a grayscale workpiece.

Simple thresholding works in controlled lighting, but factory workstations may experience lighting gradients from ambient fixtures or moving equipment.

To handle varying scene conditions, vision engineers rely on localized thresholding techniques. Adaptive thresholding calculates distinct local threshold values for small regions across an image to handle scenes with non-uniform illumination.[6]

When the lighting is uniform but the exact threshold value is unknown or shifts between production batches, automatic threshold selection is required. Otsu binarization determines an optimal global threshold automatically from a bimodal image histogram using the cv.THRESH_OTSU flag.[6] A bimodal histogram has two peaks, for example one for dark parts and one for a bright background; Otsu picks the threshold that best separates them. 

# Simple binary thresholding with fixed cutoff 127
ret1, thresh_simple = cv.threshold(gray, 127, 255, cv.THRESH_BINARY)

# Otsu automatic thresholding on bimodal grayscale input
ret2, thresh_otsu = cv.threshold(gray, 0, 255, cv.THRESH_BINARY + cv.THRESH_OTSU)

# Adaptive thresholding using local neighborhood mean
thresh_adapt = cv.adaptiveThreshold(
    gray, 255, cv.ADAPTIVE_THRESH_MEAN_C, cv.THRESH_BINARY, 11, 2
)

04. Connected components and contour geometry

After binarization, an image consists of white and black pixels. The vision processor must now organize these grouped pixels into discrete geometric entities representing individual parts. The cv::connectedComponentsWithStats function segments a binary image into labeled connected foreground components and computes bounding box geometry and pixel area for each label.[7]

The statistics matrix returned by connected component labeling gives physical parameters for every contiguous island of pixels in the image. The CC_STAT_AREA statistic output in OpenCV connected components represents the total area in pixels of the labeled component.[7] For example, vision software can filter out dust flecks or small reflection specks by rejecting components whose CC_STAT_AREA falls below a minimum pixel threshold.

Along with connected components, contour extraction traces object boundaries. In OpenCV contour detection, the object of interest must be represented as white foreground against a black background.[8] For example, if an inspection image contains dark parts against a white background, the image is inverted before finding contours.

Contours can hold many points, which costs memory and time. The contour approximation method cv.CHAIN_APPROX_SIMPLE compresses straight segments by removing redundant points along contour boundaries to save memory.[8] In OpenCV's own example, a rectangle's contour drops from 734 points to 4 corner points.[8]

From the extracted contour boundary, geometric moments provide center-of-mass coordinates. Contour centroid spatial coordinates are calculated from image moments using the relations Cx = M10 / M00 and Cy = M01 / M00.[9] The centroid (Cx, Cy) is the part position used for the pick calculations in 2.8.

05. Blob analysis with SimpleBlobDetector

In many manufacturing applications, workpieces appear as distinct spots or "blobs" of connected pixels that differ in brightness or color from surrounding areas. OpenCV provides a dedicated high-level class, SimpleBlobDetector, to identify and classify blobs according to geometric properties.

Rather than relying on a single binarization step, SimpleBlobDetector sweeps across multiple thresholds to detect features under varying contrast conditions. SimpleBlobDetector extracts candidate blobs by binarizing the source image across a range of thresholds from minThreshold to maxThreshold with increment thresholdStep.[10]

After generating multiple binary images, candidate centroids from neighboring slices must be merged into single detections. SimpleBlobDetector groups component centers from multiple binarized images that fall within minDistBetweenBlobs to establish final blob coordinates.[10] This step turns overlapping detections from the different thresholds into one point per part.

To distinguish circular parts such as washers, bearings, or bolt heads from scrap metal cuttings, the detector provides shape filters. OpenCV SimpleBlobDetector computes circularity using the formula four times pi times area divided by the square of the perimeter, where a value of 1.0 indicates a perfect circle.[11] For example, setting minimum and maximum circularity bounds allows vision systems to separate round components from irregular debris on a conveyor. 

# Configure SimpleBlobDetector parameters
params = cv.SimpleBlobDetector_Params()
params.minThreshold = 10
params.maxThreshold = 200
params.thresholdStep = 10
params.minDistBetweenBlobs = 20

# Filter candidate blobs by circularity
params.filterByCircularity = True
params.minCircularity = 0.8
params.maxCircularity = 1.0

detector = cv.SimpleBlobDetector_create(params)
keypoints = detector.detect(gray)

06. Edge detection: the Canny algorithm

When parts must be gauged or aligned with high dimensional precision, boundary edge detection is preferred over regional thresholding. Edges correspond to sharp discontinuities in surface reflectance, material boundaries, or surface geometry. The most widely used edge detection pipeline in industrial computer vision is the multi-stage Canny edge detector.

Every camera image contains some noise, and noise can create false edges. The initial step of the Canny edge detector removes image noise using a 5x5 Gaussian smoothing filter.[12]

After smoothing, the algorithm calculates image intensity gradients across horizontal and vertical directions. In cv.Canny, the aperture_size parameter configures the Sobel kernel size for computing image gradients and defaults to 3.[12]

Raw gradient maps produce thick boundaries spanning several pixels. To achieve precise geometric measurements, the edge must be thinned to a single pixel. Non-maximum suppression suppresses pixels that are not local intensity maxima along the gradient direction to produce thin single-pixel edges.[12]

The final stage resolves ambiguous edges using two separate thresholds. The Canny edge detector uses hysteresis thresholding with minVal and maxVal to distinguish true edges from noise.[12] A pixel below the lower threshold is rejected, and a pixel between the two thresholds is kept only if it is connected to a pixel above the upper threshold.[13]

07. Template matching and pattern localization

When a part features complex surface geometry, logos, or printed artwork that cannot be isolated with simple thresholding or edge filters, template matching provides direct pattern localization. Template matching slides a smaller reference patch (the template) across a larger search image to find the region of highest visual correlation.

Understanding output dimensions is essential for memory allocation and coordinate mapping. In template matching, comparing an image of size WxH with a template of size wxh produces an output match matrix of size (W-w+1, H-h+1).[14] Each entry in the resulting matrix contains a metric score indicating the degree of visual match between the template patch and that specific sub-window of the primary image.

After computing the correlation matrix with cv.matchTemplate, the software identifies the best matching location. The function cv.minMaxLoc finds the smallest and largest scores in the result and where they are. Which one marks the best match depends on the comparison method: with TM_SQDIFF, the minimum is the best match.[14]

The detected pixel coordinates directly feed robot motion commands. As established in 2.8 Vision-Guided Picking, vision software converts pixel coordinates into physical millimetres in the robot user frame via hand-eye calibration. The detected template match position defines the current part pose T_found, allowing the robot controller to shift its taught grasp points and pick the incoming part without stopping the production line.
