5.3 Encoders and Shaft Encoders

Gerald Lê Draft

01. What is an encoder?

A robot that drives “for two seconds” and hopes it went one meter is running open loop: it has no idea how far it actually moved. An encoder fixes that. It converts motion into an electrical signal, the opposite of what a motor does. Shaft (rotary) encoders mount on a motor shaft or wheel and report how far it has rotated. They give the robot a sense of where its own parts are.

02. Incremental vs. absolute

  • Incremental encoders: output a pulse (a “tick”) for each small step of rotation, and the controller counts them. They are cheap, simple and high resolution, but they only measure change: if the power goes off, the position is forgotten and the robot has to “home” to a known point again.
  • Absolute encoders: output a unique code for every shaft angle, so the controller knows the exact position the moment it powers on. They cost more and use more complex serial protocols (such as SSI or BiSS). Industrial robot arms rely on this kind of position feedback at every joint.

04. Quadrature: which way is it turning?

A single channel of pulses tells you speed but not direction. Quadrature encoders add a second channel (B) offset by a quarter cycle from the first (A). If A changes before B, the shaft is turning one way; if B changes before A, it is turning the other. Counting both the rising and falling edges of both channels gives four counts per pulse, which is why: 

CPR = PPR * 4   (counts per revolution, with 4x decoding)

Datasheets do not always use these terms the same way. If a “1000 PPR” encoder is treated as 1000 counts per turn while the code counts every edge, every distance will be off by a factor of four. The simplest check is to turn the wheel exactly one revolution by hand and see what the code reports.

05. From ticks to distance and speed

With the counts per revolution (CPR) and the wheel diameter (d), distance traveled is: 

distance = (ticks / CPR) * (pi * d)

Angular velocity over a time interval Δt, in radians per second, is: 

omega = (delta_ticks / (CPR * dt)) * 2 * pi

06. Reading an encoder in code

Encoders can produce thousands of pulses per second, far too fast to catch by calling digitalRead() in the main loop. Use hardware interrupts: the microcontroller pauses whatever it is doing when an encoder pin changes, updates the count, and returns. For demanding robots, a dedicated hardware counter (many microcontrollers have timer peripherals that can decode quadrature) frees the main processor entirely.

07. Where encoders are used

  • Odometry: encoders on the left and right wheels of a differential-drive robot let it estimate its position relative to where it started.
  • Speed control: with an encoder, a robot can hold a target speed on carpet and on hardwood alike by adjusting power, using PID control.
  • Robot arms: encoders at each joint tell the controller the exact angle of every axis.

08. Common pitfalls

  • Backlash: an encoder on the motor side of a gearbox cannot see play in the gears. Mount it close to the output when precision matters.
  • Too much resolution: a very high-resolution encoder on a slow microcontroller can generate interrupts faster than the processor can handle, so counts get missed.
  • Electrical noise: encoder signals are low voltage and high frequency. Keep them away from motor power wires and use twisted-pair or shielded cable.
  • Mounting: use a flexible coupling between the motor and encoder shafts, since no two shafts are perfectly aligned.
