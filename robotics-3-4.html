3.4 Running Your First Example (Turtlesim)

Gerald Lê

01. Turtlesim

Turtlesim is a tiny 2D simulator made for learning ROS. It draws a turtle you can drive around, and it uses the same nodes and topics as a real robot. The desktop install includes it; otherwise install it with sudo apt install ros-lyrical-turtlesim. With ROS 2 sourced, open a terminal and start the simulator: 

ros2 run turtlesim turtlesim_node

In a second terminal, start a keyboard controller and drive the turtle with the arrow keys: 

ros2 run turtlesim turtle_teleop_key

Now look at what is happening underneath. In a third terminal, list the nodes and topics, and watch the velocity commands the teleop node sends: 

ros2 node list
ros2 topic list
ros2 topic echo /turtle1/cmd_vel

The teleop node publishes velocity messages on /turtle1/cmd_vel, and the simulator subscribes to them and moves the turtle. That publish/subscribe pattern is exactly how real robots are wired together in ROS.

  • Official Turtlesim tutorial (docs.ros.org)

02. Inspecting the message

Every topic carries one message type. Ask ROS what the velocity topic carries: 

ros2 topic info /turtle1/cmd_vel

The answer is geometry_msgs/msg/Twist: geometry_msgs is the package and Twist is the message, a linear and an angular velocity. Mobile robots in ROS are commonly driven with the same message type on a cmd_vel topic, so what you practice here carries over.

03. Calling a service: spawn a second turtle

Topics stream data continuously; services answer one request at a time. Turtlesim offers several services. List them, then call /spawn to add a second turtle at a chosen position: 

ros2 service list
ros2 service call /spawn turtlesim_msgs/srv/Spawn "{x: 2, y: 2, theta: 0.2, name: ''}"

Arguments are written in YAML. An empty name lets turtlesim pick one (turtle2). On releases older than Kilted, the service type is turtlesim/srv/Spawn instead. Each turtle needs a unique name; spawning a second turtle1 prints an error.

The same can be done with a graphical tool. Install rqt (sudo apt install ros-lyrical-rqt ros-lyrical-rqt-common-plugins), run rqt, and choose Plugins > Services > Service Caller. From there you can also call /turtle1/set_pen to change the color and width of the line the turtle draws.

04. Remapping: drive the second turtle

The keyboard controller always sends commands to turtle1. Instead of changing its code, you can remap its topic and action names when you start it, so a second copy drives turtle2: 

ros2 run turtlesim turtle_teleop_key --ros-args --remap turtle1/cmd_vel:=turtle2/cmd_vel --remap turtle1/rotate_absolute:=turtle2/rotate_absolute

Each teleop terminal now drives its own turtle; the window you type in must be active to capture key presses. Remapping is how real ROS systems reuse the same node for several robots or sensors.

To finish, press Ctrl + C in the simulator’s terminal and q in each teleop terminal.

Try it
  1. Spawn a third turtle at x = 8, y = 8 and drive it with a remapped teleop.
  2. Use the /turtle1/set_pen service to draw a red line, then drive the turtle in a square.
