3.4 Robot Languages: URScript and RAPID

Gerald Lê Draft

01. Why vendor languages?

Most industrial robot makers have their own programming language, tied to their controller. Graphical tools like PolyScope cover everyday tasks, but underneath there is always a text language that exposes the robot’s full capabilities. This article introduces two widely used ones: URScript for Universal Robots cobots and RAPID for ABB industrial robots. Others you will meet include KUKA’s KRL and FANUC’s TP and KAREL.

02. URScript

URScript is the scripting language that runs on the Universal Robots controller. PolyScope programs are converted to it, and advanced users can write it directly for logic the graphical interface cannot express easily.

  • Syntax: Python-like and readable, which makes it approachable for software developers.
  • Real time: the controller runs at 125 Hz on the older CB-series robots and 500 Hz on the e-Series.
  • Motion: movej moves in joint space so all joints arrive together, movel moves the tool center point (TCP) in a straight line, and movep keeps a constant tool speed through blended paths, useful for dispensing or welding.
  • Force control: force_mode makes the robot compliant along chosen axes, for tasks like sanding or inserting parts.
  • Threads: a background thread can watch I/O or sensors while the main program keeps moving.
def pick_example():
  # joint move to a safe start pose (joint angles in radians)
  movej([0, -1.57, 1.57, -1.57, -1.57, 0], a=1.2, v=0.25)
  # straight-line move of the tool to a pose (x, y, z in m; rotation vector in rad)
  movel(p[0.30, -0.20, 0.25, 0, 3.14, 0], a=0.5, v=0.1)
  set_digital_out(0, True)   # e.g. close a gripper wired to output 0
  sleep(0.5)
end

03. RAPID

RAPID is ABB’s high-level, multitasking robot language, used on the real controller and in RobotStudio. It handles everything from simple pick-and-place to coordinating several robots.

  • Structure: a program is organized into tasks (which can run concurrently), modules (collections of data and routines), and routines: procedures (no return value), functions (return a value) and trap routines (interrupt handlers).
  • Typed data: robtarget holds a position and orientation, speeddata the tool speed, and zonedata how closely the robot passes a point, which lets it blend corners instead of stopping at each one.
  • Error handling: ERROR and UNDO handlers let a program recover from interruptions.
MODULE MainModule
    CONST robtarget pHome := [[500,0,600],[0,0,1,0],[0,0,0,0],[9E9,9E9,9E9,9E9,9E9,9E9]];

    PROC main()
        MoveJ pHome, v1000, z50, tool0;                 ! joint move, blend within 50 mm
        MoveL Offs(pHome, 0, 0, -100), v200, fine, tool0; ! straight down 100 mm, stop exactly
    ENDPROC
ENDMODULE

05. Beyond vendor languages

Because every maker has its own language, middleware such as ROS (Robot Operating System) is increasingly used to add a common layer on top. Developers write C++ or Python against ROS, and drivers translate to each robot’s native interface. Simulation tools like RobotStudio and the UR simulator also make it possible to build a digital twin of the robot to check reach and cycle time before touching real hardware.
