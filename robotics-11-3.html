      11.3 Planners, Controllers and Recoveries

      Gerald Lê

      01. Servers that host plugins

      Planners and controllers are at the heart of a navigation task.[1] Nav2 runs them inside action servers: five of its action servers are the planner, behavior, smoother, route and controller servers, and they host the algorithm plugins that do the work.[1]

      The planner, smoother and controller servers are configured at runtime with the names and types of the algorithms to use.[1] For example, the DWB controller can be given the name FollowPath, and all of its parameters then sit under FollowPath.<param>.[1] 3.5 described the same plugin structure from a contributor’s side.

      02. Planners

      A planner computes a path that completes some objective function, and it has access to the global environmental representation (11.2).[1] In Nav2 its general task is to compute a valid, and potentially optimal, path from the current pose to a goal pose.[1] Planners can also be written to compute complete-coverage paths, or paths along sparse or predefined routes.[1]

      03. Smoothers and the route server

      A smoother receives a path and returns an improved version. Smoothers typically reduce path raggedness and smooth abrupt rotations, and they can also increase the distance from obstacles and high-cost areas.[1]

      The route server is a specialized planner. It computes a route through a predefined navigation graph, not through the free-space costmap.[1] The graph can represent lanes, areas the robot is allowed to navigate, or a teach-and-repeat route.[1]

      04. Controllers

      Controllers, known as local planners in ROS 1, follow the globally computed path or complete a local task.[1] A controller uses the local environmental representation to compute feasible control efforts for the base, and many controllers project the robot forward in space at each update.[1] Following a path is the usual job, but controllers can also be written to dock with a charging station or board an elevator.[1]

      05. Behaviors and recovery

      Recovery behaviors deal with unknown or failure conditions and handle them autonomously.[1] If a perception fault fills the costmap with fake obstacles, a clear-costmap recovery lets the robot move again. If the robot is stuck, backing up or spinning in place, where that is permissible, can move it into free space.[1] After a total failure, a recovery can call an operator’s attention for help.[1]

      06. Waypoints and fleets

      The nav2_waypoint_follower sends the robot to several destinations and has a plugin interface for a task at each one, such as taking a picture, picking up a box or waiting for user input.[1] Nav2 describes two schools of thought for fleets: a dumb robot with a smart centralized dispatcher, or a smart robot with a dumb one.[1] In the first, a request to the waypoint follower is one unit of work, such as one pick in a warehouse, after which the robot returns to the dispatcher for its next task.[1]

      Try it
      1. For each job, name the Nav2 server that does it: finding a way across the building; steering around a cart that has just been left in the aisle; freeing the robot after its costmap fills with obstacles that are not there.
      2. A site wants its robots to drive only along marked lanes. Which server fits, and what does it need that a free-space planner does not?
      3. A warehouse dispatcher already knows every robot’s pose, battery level and task. Which of the two fleet approaches is this, and what does one request to the waypoint follower stand for?
