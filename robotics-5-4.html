5.4 PID Control

Gerald Lê Draft

01. What is PID?

In robotics we rarely tell a motor “run at 50% power.” We tell it “hold exactly this speed” or “go to exactly this position,” whether it is going uphill or over a rug. A PID (Proportional, Integral, Derivative) controller is the standard way to do that. It is a closed-loop controller: it measures the error between where the robot is (from a sensor such as an encoder) and where it should be (the setpoint), and adjusts the control output, usually a PWM duty cycle, to shrink that error.

02. The three terms

The controller output is the sum of three terms: 

u(t) = Kp*e(t) + Ki*∫e(t)dt + Kd*de(t)/dt
  • Proportional (the present): “the further I am from the target, the harder I push.” P does most of the work, but on its own it usually leaves a small steady-state error, because as the error shrinks the push becomes too weak to overcome friction.
  • Integral (the past): adds up error over time, so a small error that lingers slowly builds more push until it is gone. Too much integral causes overshoot and oscillation.
  • Derivative (the future): reacts to how fast the error is changing, braking as the robot approaches the target. It damps oscillation but amplifies sensor noise.

03. PID in code

Robot controllers run in discrete time steps (for example every 10 ms), so the integral becomes a running sum and the derivative becomes a difference: 

float Kp = 1.2, Ki = 0.5, Kd = 0.1;
float lastError = 0, integral = 0;

float updatePID(float setpoint, float measured, float dt) {
    float error = setpoint - measured;
    integral += error * dt;
    float derivative = (error - lastError) / dt;
    lastError = error;
    return Kp * error + Ki * integral + Kd * derivative;  // usually converted to a PWM value
}

The gains here are only placeholders; every robot needs its own. The time step dt should be steady, so run the loop from a timer interrupt, or measure the real elapsed time each pass and use that.

04. Tuning

A safe, practical order for hand tuning:

  1. Secure the robot (for example, wheels off the ground) and set all gains to zero.
  2. Raise Kp until the system responds briskly and starts to oscillate, then back it off.
  3. Add Kd to damp the oscillation and make stops crisp.
  4. Add just enough Ki to remove the remaining steady-state error. Ki is usually much smaller than Kp.

The classic Ziegler–Nichols method gives a starting point instead of guessing. With Ki and Kd at zero, increase Kp until the output oscillates steadily. That gain is the ultimate gain Ku, and the oscillation period is Pu. Then start from Kp = 0.6 Ku, Ki = 1.2 Ku / Pu and Kd = 0.075 Ku × Pu, and refine by hand.

05. Common pitfalls

  • Integral windup: if the robot is blocked, the integral keeps growing, and when it is released it lurches. Clamp the integral, or stop integrating while the output is already at its limit.
  • Derivative kick: a sudden setpoint change makes the error jump, and the D term spikes. Take the derivative of the measurement instead of the error.
  • Sensor noise: the D term amplifies jitter. Low-pass filter the derivative or the sensor reading.
  • Step setpoints: jumping the target straight to its final value slams the motor. Feed the controller a motion profile (for example a trapezoidal velocity profile) of small intermediate setpoints instead.

06. Going further

  • Feed-forward: if you know roughly how much power a motion needs (for example to hold an arm up against gravity), add it directly and let PID handle only the correction.
  • Cascaded loops: an outer position loop sets the target for a faster inner velocity loop, so the robot reacts to disturbances before the position error grows.
  • Gain scheduling: switch to a different set of gains when the robot’s behavior changes, such as an arm carrying a heavy load.
  • Reusable code: wrap PID in a class with its gains and limits, so the left wheel, right wheel and gripper can each have their own controller built from the same tested code.

07. Which controller when?

ControllerTypical useResult
PSimple systems that tolerate a small offsetFast, but settles slightly off target
PISpeed control, like cruise controlReaches the exact target, can be sluggish
PDPosition control of a servo or gimbalFast with little overshoot, may leave a small offset
PIDPrecise arms and balancing robotsAccurate and stable when well tuned
