5.8 Intro to Kalman Filters

Gerald Lê

01. Why fuse sensors?

The last few lessons left us with a problem. Odometry is smooth and responds instantly, but it drifts: its error grows the farther the robot drives. An ultrasonic sensor measuring the distance to a known wall, or GPS outdoors, does not drift, but each reading is noisy and some are badly wrong. Neither is good enough alone (see 5.5).

A Kalman filter combines the two. It keeps a best estimate of the robot’s state together with a number saying how uncertain that estimate is, and it weighs each new piece of information by how trustworthy it is. The result is usually better than either source on its own.

02. The predict–update cycle

A Kalman filter repeats two steps forever:

  • Predict (time update): use what the robot did, such as the distance its encoders say it drove, to move the estimate forward. Because motion is imperfect, uncertainty grows.
  • Update (measurement update): use what the robot sensed to correct the estimate. Because we learned something, uncertainty shrinks.

Uncertainty is measured as a variance, written P: the square of the standard deviation. A small P means “I am fairly sure,” a large P means “I could be way off.”

03. A one-dimensional Kalman filter

Picture a robot driving along a hallway. Its state is a single number x, its position in meters. Each step we have a motion input u (from odometry) and a measurement z (from a range sensor, converted to a position). 

Predict:  x_pred = x + u
                                      P_pred = P + Q

                            Update:   K = P_pred / (P_pred + R)
                                      x = x_pred + K * (z - x_pred)
                                      P = (1 - K) * P_pred
  • x_pred = x + u: “I was at x and moved u, so now I am probably at x + u.”
  • P_pred = P + Q: moving adds uncertainty. Q is the process noise, how much error one motion step adds.
  • K, the Kalman gain: a number between 0 and 1 that says how much to trust the measurement. R is the measurement noise, the variance of the sensor. If the prediction is uncertain (P_pred large) compared with the sensor (R small), K is close to 1 and the filter follows the sensor. If the sensor is the noisy one, K is close to 0 and the filter mostly keeps its prediction.
  • z − x_pred: the innovation, how far the measurement is from what we expected. The estimate moves by K times this gap.
  • P = (1 − K) P_pred: after a measurement the estimate is more certain than before.

04. A worked example

The robot believes it is at x = 2.00 m with variance P = 0.04 (a standard deviation of 0.2 m). Its encoders say it just drove u = 0.50 m, and we model each step’s process noise as Q = 0.01. The range sensor then reports z = 2.60 m, and its noise variance is R = 0.05. 

Predict:  x_pred = 2.00 + 0.50          = 2.50 m
                                      P_pred = 0.04 + 0.01          = 0.05

                            Update:   K      = 0.05 / (0.05 + 0.05) = 0.5
                                      x      = 2.50 + 0.5 * (2.60 - 2.50) = 2.55 m
                                      P      = (1 - 0.5) * 0.05     = 0.025

Because the prediction and the sensor were equally uncertain (both 0.05), K = 0.5 and the new estimate lands exactly halfway between them, at 2.55 m. Notice that the new variance, 0.025, is smaller than both 0.05 values: combining two uncertain sources gives a more certain answer than either alone.

05. In code

float x = 0.0;          // position estimate (m)
                            float P = 1.0;          // variance of the estimate: start unsure
                            const float Q = 0.01;   // process noise: how much each move adds
                            const float R = 0.05;   // measurement noise: variance of the sensor

                            void kalmanPredict(float u) {     // u = distance moved, from odometry
                              x = x + u;
                              P = P + Q;
                            }

                            void kalmanUpdate(float z) {      // z = position measured by the sensor
                              float K = P / (P + R);
                              x = x + K * (z - x);
                              P = (1 - K) * P;
                            }

Call kalmanPredict() every time odometry updates, and kalmanUpdate() only when a new sensor reading arrives. If a reading is missing or obviously invalid (for example, an ultrasonic timeout), simply skip the update: the filter keeps predicting and P keeps growing, which is exactly right.

06. Choosing Q and R

  • R: measure it. Hold the robot still, take many sensor readings, and compute their variance.
  • Q: usually tuned. A larger Q says “my motion model is unreliable” (slippery floor, wheels that slip), so the filter leans on the sensor and reacts faster but is jumpier. A smaller Q trusts the model, giving a smoother estimate that is slower to correct.
  • Only the ratio matters for K: after a few steps, the gain settles to a value set by how big Q is compared with R. Doubling both Q and R leaves the settled gain unchanged.

07. Real robots

A real robot’s state has several numbers (x, y and θ, often plus velocities), so the filter uses vectors and matrices instead of single numbers, but the predict–update cycle is identical. The basic Kalman filter assumes linear motion and measurements. Turning and driving involve sines and cosines, so mobile robots usually use the extended Kalman filter (EKF), which linearizes the equations around the current estimate at each step.

For estimating tilt from an IMU, many small robots use a simpler complementary filter instead. The gyroscope is trusted over short time spans and the accelerometer, which knows where gravity points, over long ones: angle = 0.98 * (angle + gyroRate * dt) + 0.02 * accelAngle. The weights here are a common starting point, not a rule.

08. A little history

Rudolf E. Kálmán published the filter in 1960 in “A New Approach to Linear Filtering and Prediction Problems,” a recursive solution that suited the digital computers then appearing. That autumn he visited Stanley Schmidt at NASA Ames Research Center, whose group was studying navigation for the Apollo lunar missions. Schmidt’s team turned the idea into a practical tool, developing what became the extended Kalman filter, and a square-root form of the filter was used in the Apollo system. Today Kalman filters run in everything from phones to aircraft to self-driving cars.

Try it
  1. Repeat the worked example with R = 0.01 and then R = 0.5. Calculate K each time and explain which way the estimate moves.
  2. Write the 1-D filter in Python or C++ and feed it ten noisy readings of a constant value. Plot the raw and filtered values.
