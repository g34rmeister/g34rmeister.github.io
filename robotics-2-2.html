2.2 Common Programming Environments

Gerald Lê Draft

01. RobotStudio

ABB RobotStudio is offline programming and simulation software for ABB industrial robots. It lets engineers program, configure and test a robot system on a PC without disturbing the physical production line.

RobotStudio is built on ABB’s Virtual Controller, a copy of the same software that runs the real robot controller. Because the simulated robot runs the same controller software as the real one, programs developed offline can move to the real robot with little adjustment.

  • Offline programming: create and refine robot programs on a PC, reducing risk and shortening installation time.
  • Simulation and validation: 3D simulation for reachability studies, collision detection and cycle-time optimization.
  • Virtual commissioning: test how the robot interacts with PLCs and other equipment before the hardware is installed.
  • CAD import: bring in 3D models of parts and fixtures (in formats such as STEP and IGES) to build an accurate virtual work cell.
  • PowerPacs: add-ins for specific applications such as arc welding, machining, palletizing and painting.

Benefits

BenefitDescription
Lower riskFind collisions and design flaws in the virtual world before they cause damage in the real one.
Faster start-upPrepare programs in advance to shorten the time from installation to production.
Higher productivityModify and optimize programs without stopping the robots that are running.

Programs in RobotStudio are written in RAPID, ABB’s high-level robot language. The built-in editor provides syntax coloring, tooltips and error checking. RobotStudio runs on Windows, and large simulations with several robots or big CAD models benefit from a PC with a dedicated graphics card.

02. PolyScope

PolyScope 5 is the graphical interface and operating software that Universal Robots (UR) runs on the teach pendant of its e-Series collaborative robots. It is designed to make robot programming accessible to people without a coding background, and it guides the user from setting up the robot to running it in production.

  • Touch-first layout: large buttons and a small set of main tabs, including Run, Program, Installation and Move.
  • Program tree: programs are built by adding commands such as Move, Wait, If and Loop as nodes in a tree, rather than typing code.
  • 3D view: a live view of the robot and its programmed path gives immediate visual feedback during setup.
  • Move tab and freedrive: the robot can be jogged with on-screen arrows, or put into freedrive so the operator can guide it by hand to each waypoint (lead-through programming).

Core capabilities

FeatureWhat it does
Safety configurationDefine limits such as restricted zones, speed and force thresholds as part of the robot setup.
URCapsPlug-ins that let third-party grippers, sensors and vision systems integrate with the interface.
Setup wizardsStep-by-step calibration of the tool center point (TCP), payload and center of gravity.

When the GUI is not enough

PolyScope is mainly a no-code environment, but advanced users are not locked in. A Script node lets a program run URScript, the Python-like language underneath PolyScope. Programs can also track digital and analog I/O and user variables, and make decisions with If/Else and Switch nodes.

Why it matters

  • Lower barrier to entry: floor operators can adjust waypoints and troubleshoot without a dedicated robotics engineer.
  • Faster setup: simple tasks can be programmed directly at the robot with little training.
  • Safety by default: because safety limits are configured in the same interface, the robot’s speed and force limits apply even when programs call URScript underneath, which is what allows cobots to share space with people.
