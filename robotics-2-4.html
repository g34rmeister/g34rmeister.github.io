2.4 Intro to ROS (Vendor-Agnostic)

Gerald Lê

01. One layer for every robot

Every robot maker has its own language and tools, so skills and code do not carry over from one brand to another. Middleware such as ROS (Robot Operating System) adds a common layer on top. Developers write C++ or Python against ROS, and drivers translate to each robot’s native interface.

ROS is used especially widely in mobile robotics, and simulators let developers build a digital twin of a robot to test code before touching real hardware.

02. ROS-Industrial

ROS-Industrial is an open-source project that extends ROS to manufacturing. It began in January 2012 as a collaboration between Yaskawa Motoman, Southwest Research Institute (SwRI) and Willow Garage, when Shaun Edwards at SwRI started its code repository. It focuses on what factories need: interfaces for industrial arms, sensors and grippers, plus calibration, perception and motion planning.

Companies and research groups support the project through regional consortia: ROS-Industrial Consortium Americas, launched in March 2013 and led by SwRI; a European consortium led by Fraunhofer IPA in Germany; and an Asia Pacific consortium led by ARTC and Nanyang Technological University in Singapore.

03. Vendor drivers: a Universal Robots example

A ROS driver is the piece that translates between ROS and a specific robot’s controller. Some robot makers publish their own. Universal Robots, for example, officially provides and supports drivers for both ROS and ROS 2 (the Universal_Robots_ROS2_Driver repository on GitHub). According to Universal Robots, the ROS 2 driver:

  • Works with MoveIt: so arm motion can be planned with the standard ROS motion-planning tools.
  • Uses factory calibration: the robot’s own calibration data, for more precise Cartesian targets.
  • Communicates in real time: using the controller’s 2 ms cycle time.
  • Replaces the teach pendant for control: robot functions are exposed as ROS services and actions.

Because the driver presents the robot as ordinary ROS topics, services and actions, code written against it looks much like code for any other ROS robot. That is the vendor-agnostic idea in practice.
