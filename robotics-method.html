How This Course Was Made

Gerald Lê

RISE Bot Instructor is Gerald Lê's honors research project (CSC 3991, Louisiana State University, Spring 2026, advised by Felipe Fronchetti). This page explains where the lessons came from, how their sources were chosen and checked, and where AI tools were used along the way, so that readers and reviewers can judge how far to trust them.

01. What the course is built from

The structure follows Gerald's research proposal and roadmap: an introduction to robots, how industrial robots are programmed (teach pendant, offline and block-based), the Robot Operating System (ROS), and the ethics of building robots. An optional fifth chapter on electronics and control (Arduino, PWM, encoders, PID, sensors, odometry, state machines and Kalman filters) covers a list of topics Gerald set out to explore. His advisor's feedback asked for more hands-on work, visuals and photos, and a quiz, which is why lessons have Try it boxes, diagrams, simulators and chapter quizzes.

02. Sources policy

  • Every factual claim is cited. Each lesson marks claims with a numbered link such as [3] that jumps to its References list, numbered in order of first use.
  • Primary sources first. The preferred sources are standards bodies (ISO, IEC), vendor manuals (ABB, Universal Robots, FANUC, Arduino), the official ROS documentation, the International Federation of Robotics, and peer-reviewed papers. Encyclopedias and tutorials are used only for background.
  • No source, no claim. A statement that could not be traced to a source was removed or reworded as an open question, not guessed.
  • Current versions. The course targets ROS 2 Lyrical Luth (May 2026), ISO 10218:2025 and IFR World Robotics 2026. Older releases are named where students may still meet them.

03. How AI tools were used

AI tools helped research and draft much of the text. They did not decide what the course covers, and nothing they wrote was published without a check against sources.

Part How it was drafted How it was checked
First drafts (all chapters) Gerald's own notes and drafts. Some background documents were generated with Google Gemini and were marked as unverified. A fact check against primary sources fixed outdated claims, such as the current ROS 2 release and the 2025 revision of ISO 10218, and found that “RRL” is not a language on today’s commercial robots, so lesson 2.3 now presents it as history next to KUKA’s KRL.
Chapter 1 (lessons 1.1 to 1.6) Researched and rewritten with Claude (Anthropic), with one research pass per lesson. Each lesson came with research notes listing every source. Corrections, such as the Czech premiere dates of R.U.R. and the World Trade Center robot deployments, were made before the text was expanded.
Chapters 2 to 5 (lessons 2.1 to 5.8) Expanded with Google Gemini. Claude audited every reference in all 20 lessons. Invented references were replaced with real sources, wrong figures were corrected (for example the ISO/TS 15066 contact-force limits), and quiz questions that relied on removed facts were rewritten.
Added lessons (1.7, 2.5, 2.6, 3.6, 3.7 and 4.4) Researched and written with Claude (Anthropic), one research pass per lesson. Each lesson came with research notes listing every source. The research could open only GitHub-hosted pages, such as the ROS 2 documentation source, so many references in 1.7, 2.5, 2.6 and 4.4 were cited from search summaries and are being checked by Gerald against the original pages.
Added lessons (2.7, 2.8, 3.8, 3.9, 4.5, 5.9 and 5.10) Researched and written with Claude (Anthropic), one research pass per lesson, using the same process as the lessons above. The same access limit applied. 3.8 is cited entirely from opened pages (the MoveIt 2 and ROS 2 documentation source on GitHub). Many references in 2.7, 2.8, 4.5 and 5.9 come from search summaries and are being checked by Gerald against the original pages.
Chapter 6 capstone projects (6.1, 6.2 and 6.3) Researched and written with Claude (Anthropic), one research pass for the chapter, using the same process as the lessons above. The same access limit applied. Software and library steps come from documentation opened on GitHub. Most of the teaching-practice and hardware-supplier sources come from search summaries, and the rubric level names in the middle two columns are the course's own.
Source check (all lessons, October 2026) Google Gemini, run from the Antigravity command line, proposed candidate sources and the exact words in each source that should support each cited sentence. It did not edit lessons. A script fetched every proposed page and kept only words that actually appear in it; Claude then read the matches and edited the lessons. Gemini’s own “supported” labels were often wrong, so none were accepted unchecked. Dead links were replaced, wrong attributions and figures were corrected, and claims no readable source supports were removed. Of 1,090 references, 975 now match their source text, 43 support only part of their sentence and 72 could not be opened (paywalls, books and blocked sites).
Diagrams, simulators and quizzes Written with Claude to match the lesson text. Quiz answers are tested against the lesson text, and every simulator is tested in a browser on desktop and phone widths.

The audit logs and research notes are kept with the project files. The full history of every change is public in the site's GitHub repository.

04. Review before publishing

  1. Every change is made on a separate branch and opened as a GitHub pull request that describes what changed and why.
  2. Automated checks run on each pull request: every internal link and every citation link must resolve, every page must follow the shared accessibility and metadata conventions, and the course data (objectives, key terms and quiz answers) must match the lessons.
  3. The lessons are opened in a real browser at desktop and phone widths to catch layout and script errors.
  4. Gerald approves the pull request before it goes live.

05. Known limits

  • Checking reduces errors but does not remove them. AI-assisted text can still contain a wrong detail that a source check missed.
  • Some standards (ISO 8373, ISO 10218, ISO/TS 15066) are sold, not free. Where the full text was not available, lessons rely on the official preview samples or on summaries from standards bodies and industry groups.
  • Software moves fast. Install steps and release names were correct when written and may change with the next ROS release.

If you find an error, please report it through the contact page with the lesson number and, if you can, a source.
