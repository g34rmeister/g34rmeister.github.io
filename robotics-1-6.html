1.6 Robot Anatomy and Coordinate Frames

Gerald Lê

01. Links and joints

A robot arm is a chain of rigid links connected by motorized joints. There are two kinds of joint:

  • Revolute (rotary): the link rotates about the joint axis, like an elbow.
  • Prismatic (linear): the link slides along the joint axis, like a drawer. The up-and-down axis of a SCARA robot is an example.

Each joint adds one degree of freedom (DOF). Data sheets call the joints axes, numbered from the base outward.

02. Why six axes?

A rigid object in three-dimensional space has six degrees of freedom: three for its position (x, y, z) and three for its orientation (rotation about each of those directions). To place a tool at a chosen position and point it in a chosen direction, the arm generally needs at least six joints. That is why the typical industrial arm is a six-axis robot with six rotary joints.

Roughly speaking, the first three axes (base, shoulder, elbow) decide where the wrist is, and the last three axes form the wrist, which turns the tool in roll, pitch and yaw. A robot with fewer axes cannot reach every orientation. A four-axis SCARA robot, for example, can only turn its tool about the vertical axis.

03. End effector and workspace

The end effector is the tool mounted on the wrist flange: a gripper or vacuum cup for picking parts, a spot-welding gun, an arc-welding torch. Changing the end effector changes the job.

The workspace (often called the work envelope in industry) is the region the end effector can reach. Near its edges the robot can reach a point only with a limited range of tool orientations, so important work is placed well inside it.

04. Coordinate frames

A position such as “x = 500 mm” only means something once you say where it is measured from. Controllers use several coordinate frames (ABB’s names below; other vendors use similar ones):

  • World frame: a fixed frame for the whole cell.
  • Base frame: fixed at the base of the robot.
  • Tool frame and TCP: the tool center point (TCP) is the working point of the tool, such as the tip of a welding wire or the center between gripper fingers. Every ABB robot has a predefined tool, tool0, whose TCP sits at the tool mounting flange. For a real tool you define a new tool frame so the controller knows where its tip is.
  • Work object (user frame): a frame attached to the fixture or workpiece. In ABB robots it consists of a user frame and an object frame, and all program targets are measured relative to it. The default work object, wobj0, coincides with the robot’s base frame.

Defining frames is what makes a program reusable. If the fixture is placed a little differently in the real cell than in simulation, or moved to another spot, you re-teach the work object and every target moves with it; the program itself does not change.

05. Joint space, Cartesian space and kinematics

In joint space you describe the robot by the angle of every joint. In Cartesian space (task space) you give the position and orientation of the TCP in some frame. Kinematics converts between them:

  • Forward kinematics: from known joint angles, calculate where the tool is and how it is oriented. There is always exactly one answer.
  • Inverse kinematics: from a desired tool pose, calculate the joint angles that achieve it. This is harder: there may be several solutions (for example elbow up or elbow down) or none at all if the pose is out of reach.

The controller does this for you: given a pose, a Universal Robots movej uses inverse kinematics to find the joint positions.

06. Motion types

A move instruction also says how to get there (the interpolation). ABB (MoveJ, MoveL, MoveC) and Universal Robots (movej, movel, movec) offer the same three basic types:

MovePath of the toolTypical use
Joint (MoveJ / movej)Interpolated in joint space: all joints start and arrive together, and the tool follows a curved path that is not a straight lineFast moves through free space, such as going to a home or approach position
Linear (MoveL / movel)The TCP moves in a straight line in Cartesian spaceApproaching a part, inserting, welding a straight seam
Circular (MoveC / movec)The TCP follows an arc from the current position, through a via point, to the targetWelding or dispensing along a curved edge

Linear and circular moves need inverse kinematics along the whole path, so they can fail near singularities, poses where a small tool motion needs very fast joint motion. A joint move to joint angles is not affected. Use joint moves where the path does not matter, and linear or circular moves where it does.

Blending: stopping exactly at every point wastes time. A zone (ABB’s zonedata, such as z50) or blend radius (the r parameter in URScript) lets the robot round the corner without stopping. Use a stop point (ABB’s fine, or r=0) where accuracy matters, such as the moment a gripper closes.

Connecting to lesson 2.3

The RAPID example in 2.3 Robot Programming Languages uses all of these ideas. pHome is a robtarget, a Cartesian position and orientation. MoveJ pHome, v1000, z50, tool0 is a joint move that blends within 50 mm, and MoveL ... fine, tool0 is a straight-line move that stops exactly. Both use tool0, so the TCP is the bare mounting flange, and because no work object is given, the targets are measured in wobj0, the base frame.

Try it
  1. Hold your arm out and count its degrees of freedom from shoulder to wrist. Which joints are revolute?
  2. In the RAPID example from 2.3, name the tool and the work object it uses, and say what would change if the part moved 5 cm.
