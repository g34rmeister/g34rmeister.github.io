2.1 Types of Programming

Gerald Lê

01. Offline programming

Offline programming (OLP) means building the robot program on a computer, in software that simulates the robot and its work cell in 3D. The real robot does not need to be present, so it can keep working while the next program is written and debugged in simulation. When the program is ready, it is downloaded to the robot.

All major robot makers offer offline software, either text-based or graphical: for example FANUC ROBOGUIDE, Yaskawa MotoSim and ABB RobotStudio (covered in its own article).

AdvantagesDisadvantages
Less robot downtime, since programming happens without the robotExtra cost; offline software is usually sold as an option
Saves time on complex programs compared with entering each step by handNeeds a computer and additional software
Simulation catches errors before they reach the real robotMay require extra training

02. Online programming

Online programming means taking the robot out of production, putting it into programming (teach) mode, and creating or editing the program on the robot itself. There are two main methods:

  • Teach pendant: industrial robots normally come with a handheld pendant connected to the controller. The programmer jogs the robot to each position and records the steps of the program through the pendant’s interface. It is the most common way industrial robots are programmed: EU Automation’s Jonathan Wilkins puts the share at over 90%, though this is an industry estimate rather than a published survey.
  • Lead-through (hand guiding): the programmer physically guides the robot arm through the waypoints of the task, and the robot records them. This is the main programming method for collaborative robots (cobots), and because it is so intuitive it is a good fit for people new to automation.
AdvantagesDisadvantages
No extra hardware or software neededThe robot is out of production while it is programmed
Most technicians already know teach pendantsPendants use brand-specific languages
Well suited to simpler applicationsLead-through lacks precision

03. Block-based (visual) programming

Block-based programming is a graphical form of programming in which commands are shown as blocks that the user drags onto the screen and snaps together, like puzzle pieces. A block might mean “move to this point,” “close the gripper” or “repeat 10 times,” and the shapes of the blocks show which ones fit together. This is the style many students know from Scratch. The Blockly library, an open-source project of the Raspberry Pi Foundation supported by Google, lets software makers add the same kind of block editor to their own apps.

The robot does not run the blocks themselves. In a Blockly-based editor, each block is defined to produce a piece of text code, and the editor joins the pieces from the connected blocks into one program. In robot tools that program is written in the robot’s own language, which the controller then runs as usual.

  • ABB Wizard Easy Programming: launched in 2020 for the single-arm YuMi cobot and built on the Blockly concept. Programs are assembled on the FlexPendant and converted in real time into ABB’s RAPID language. ABB has since extended it to its other cobots (including GoFa and SWIFTI) and, in 2023, to six-axis industrial robots with the OmniCore controller.
  • Universal Robots PolyScope: a related graphical approach. Instead of puzzle blocks, the program is a tree of nodes such as Move, Wait and If, and PolyScope combines the nodes into a URScript program that is sent to the controller (see 2.2).
  • Educational robots: the LEGO Education SPIKE app moves from icon and word blocks based on Scratch to text-based Python, and VEX Robotics’ VEXcode Blocks is powered by Scratch Blocks.
AdvantagesDisadvantages
No syntax to learn, so typing errors such as a missing bracket cannot happenLarge or complex programs become hard to read on screen
Operators without programming experience can build and adjust simple tasksNot every feature of the native language is available as a block
Experts can wrap complex code in a single custom block for others to useEach vendor’s blocks are different, so skills transfer only partly

Block-based programming fits simple, frequently changed tasks such as pick-and-place on a cobot, and teaching. For complex logic, a common pattern is that an expert writes the hard parts in the native language and packages them as blocks that floor operators can arrange.

04. Which to use

Online programming is quick and simple for small jobs and small changes. Offline programming pays off for complex programs, for lines that cannot afford downtime, and for checking reach and collisions before equipment is installed. In practice many teams use both: they build the program offline and then touch up a few positions on the real robot with the pendant.

05. Example: a welding cell

Industrial programming centers on repeatability, safety and deterministic logic. In a spot-welding cell, for example, a six-axis arm follows a path built from joint moves (MoveJ) and straight-line moves (MoveL) defined relative to a work object and tool center point, and the program must fire the welder exactly when the arm reaches each point. Increasingly these paths are developed offline in simulation to avoid stopping production.

Try it
  1. Pick a job (palletizing boxes, welding a frame, sorting parts on a bench) and choose online, offline or block-based programming for it. Explain your choice.
  2. Try a free Blockly demo in your browser (see blockly.com) and look at the code the blocks generate.
