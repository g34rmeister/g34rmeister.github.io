      11.1 Where Is the Robot? Frames, Odometry and Localization

      Gerald Lê
      Chapter 11, lesson 1 of 4 ← Previous: Chapter 11 overview Next: 11.2 Costmaps: How the Robot Sees Its Surroundings →

      01. From a fixed arm to a moving base

      An industrial arm is bolted down, so every position can be measured from its base (1.6). A mobile robot has to work out where it is before it can plan a route. This chapter uses Nav2, the ROS 2 navigation project introduced in 3.5 Case Study: Contributing to Nav2, as its worked example. It also builds on the wheel odometry in 6.6 Odometry.

      Nav2 does not require a lidar. Its documentation says there is no requirement to use lidar-based collision avoidance, localization or SLAM, and that a vision or depth based positioning system can be equally successful, as long as the standards below are followed.[1]

      02. Three coordinate frames

      ROS mobile robots share a set of frame names. They come from REP 105, which Nav2 describes as defining the frames and conventions required for navigation.[1]

      • base_link is rigidly attached to the mobile robot base.[2]
      • odom is a world-fixed frame in which the robot’s pose is guaranteed to be continuous: it evolves smoothly, without discrete jumps. The price is drift, which can grow over time without any bounds.[2]
      • map is a world-fixed frame in which the pose should not significantly drift over time. It is not continuous: the pose can change in discrete jumps at any time.[2]

      Each frame suits a different job. REP 105 calls odom useful as an accurate, short-term local reference, and map useful as a long-term global reference but a poor frame for local sensing and acting.[2]

      03. The transform chain Nav2 needs

      Nav2 needs two major transformations: map to odom, provided by a positioning system (localization, mapping or SLAM), and odom to base_link, provided by an odometry system.[1] At minimum, the robot must build a transform tree with the full chain: map, odom, base_link, then its sensor frames.[1]

      The tree is kept by TF2, the time-variant transformation library in ROS 2.[1] The remaining transforms, from base_link to each sensor, should be static and defined in the robot’s URDF.[1]

      04. Odometry: smooth, but it drifts

      The odometry system provides the odom to base_link transform, and its goal is a smooth and continuous local frame based on robot motion.[1] Odometry can come from many sources, including lidar, radar, wheel encoders, visual-inertial odometry (VIO) and IMUs.[1] 6.3 and 6.6 worked through the wheel-encoder version, and 6.5 covered the IMU.

      One source is rarely enough. Nav2’s documentation says the robot_localization package is typically used to fuse them: it takes in N sensors of various types and provides a continuous and smooth odometry.[1] A typical setup fuses wheel encoders, IMUs and vision.[1] The fused output can then be used for dead reckoning between global position updates.[1] 6.8 Intro to Kalman Filters introduces one common way of fusing sensors.

      05. Global positioning: correcting the drift

      The global positioning system (GPS, SLAM or motion capture) must, at minimum, provide the map to odom transform.[1] It updates that transform to account for the odometric drift.[1] This is why the map frame jumps: a localization component keeps re-computing the robot pose from sensor observations, which removes drift but causes discrete jumps when new sensor information arrives.[2]

      Nav2 provides two tools for this. amcl is an Adaptive Monte-Carlo Localization technique based on a particle filter, for localization in a static map.[1] SLAM Toolbox is the default SLAM algorithm, used to position the robot and generate a static map.[1]

      06. Check your understanding

      • Which of the two frames, odom or map, is continuous, and which one does not drift?
        Show answer

        The odom frame is continuous: the robot’s pose evolves smoothly, without discrete jumps, although it drifts over time. The map frame is the one that does not significantly drift, but it is not continuous. (Section 02)

      • Which system provides the map to odom transform, and which provides odom to base_link?
        Show answer

        The map to odom transform is provided by a positioning system (localization, mapping or SLAM). The odom to base_link transform is provided by an odometry system. (Section 03)

      • What is the difference between what amcl and SLAM Toolbox are used for?
        Show answer

        amcl is an Adaptive Monte-Carlo Localization technique based on a particle filter, used for localization in a static map. SLAM Toolbox is the default SLAM algorithm, used to position the robot and generate a static map. (Section 05)

      Try it
      1. A robot drives a 20 m loop and returns to its start. Its wheels slipped on the way. In which frame is its reported pose now wrong, and which component corrects it?
      2. Sketch the transform tree for a robot with one lidar and one camera. Label each link with who provides it: localization, odometry or the URDF.
      3. A controller needs a pose that never jumps between two control cycles. Which frame should it work in, and why would the other frame be a poor choice?
